# brand 페이지 작업 기록

`pages/brand/` 페이지의 작업 내역입니다.
대상 화면은 Figma `4조 한복판 - 차이킴` node `1707:6120`("brand_송명희", 13440 × 11260)입니다.

캔버스가 13440px로 넓은 이유는 `mood`(3장면)와 `tchaikim`(5장면) 두 섹션이
**시안에서 가로로 늘어서 있기** 때문입니다. 세로로 읽는 페이지 본체는 1920px 폭입니다.

> **`mood`는 맨 아래 여섯 항목이 최신입니다** ("한 번의 흐름으로…", "배경을 사진
> 한 장으로 고정", "무드 단어 사진 복원 + gap 15", "흐름 속도 절반으로 + 둥둥 흔들림",
> "문 열림 속도 조절 + 글 상자 둥둥 제거 + 버벅임 대책",
> "배경 사진을 무대 전체로 확대").
> 움직임 조절값은 `pages/brand/js/brand.js` 위쪽 한 블록,
> 무대 높이와 배경 위치는 `css/brand.css`의 `.mood` 안 `--mood_*` 변수에 있습니다.
> 1차 구현의 가로 3패널 스크롤은 페이지 진입 시 저절로 재생되는 인트로로 바뀌었고,
> 그 인트로의 타임라인도 다시 한 번 바뀌었습니다. 1차 구현 항목에서 mood에 관한 내용
> (섹션 구성표의 mood 행, 가로 스크롤, 검증값)과 "자동 인트로로 다시 만듦" 항목의
> 타임라인 표·`.mood_words` 설명은 더 이상 유효하지 않습니다.
> `tchaikim` 관련 내용은 그대로 유효합니다.

데스크톱 1920 기준 전체 섹션을 구현했습니다. **반응형(360 / 768 / 1280)은 다음 단계입니다**
(다른 페이지와 같은 정책).

기존 파일이 `.jpg`인 것과 달리 이 5장은 Figma가 내보낸 원본 그대로 `.png`입니다.

### 섹션 구성

| 섹션 | 시안 크기 | 내용 |
|---|---|---|
| `mood` | 1920 × 700 × **3장면** | 닫힌 문(검정) → 열리는 중(실내 사진 + 글) → 활짝 열림(글 + 무드 3단어) |
| `kimyoungjin` | 1920 × 2499 | 올리브→회색 그라디언트. Origin / Traditional / Handmade |
| `tchaikim` | 1920 × 1120 × **5장면** | Everyday / Forward / Seasons / Obangsaek / Woven, 각 장면에 영상 1개 |
| `atelier` | 폭 2380 | 사진 7장 + "Where craftsmanship lives." |
| `heritage` | 1920 × 1080 × 4 | "Find Your Difference" → 과거·현재·지금 사진 3장 → Bespoke 버튼 |

`mood`의 2·3장면은 **같은 글("Refined into elegance")을 반복**합니다.
2장면은 글이 오른쪽(x 1152~1920), 3장면은 왼쪽(x 0~768)에 있고 오른쪽이 무드 단어 패널로 채워집니다.
문이 열리면서 글이 왼쪽으로 밀려나고 안쪽이 드러나는 연출입니다. 시안 그대로 두 벌 배치했습니다.

### 가로 스크롤 (`js/brand.js`)

`mood`와 `tchaikim`은 화면을 붙잡아 둔 채(`pin`) 트랙을 왼쪽으로 미는 방식입니다.

- 이동 거리 = `1920 × (패널 수 − 1)`. mood 3840, tchaikim 7680.
- `scrub: 1`, `pin: true`, `invalidateOnRefresh: true`.
- **기본 HTML/CSS는 패널이 세로로 쌓인 상태**입니다. `js/brand.js`가 `is_horizontal`을
  붙였을 때만 가로로 바뀝니다. JS나 GSAP이 없어도 내용은 전부 읽힙니다.
- `gsap.matchMedia()`로 **1280px 이상 + 모션 감소 설정이 아닐 때만** 적용합니다.
  조건이 어긋나면 GSAP이 되돌리고, 정리 함수가 `is_horizontal`도 함께 뗍니다.

조절값은 `js/brand.js` 상단에 있습니다: `HORIZONTAL_MIN_WIDTH`(1280), `PANEL_WIDTH`(1920).

### 영상 5개

`preload="none"`으로 두고, `IntersectionObserver`가 `tchaikim` 섹션에 들어올 때
(`rootMargin: 200px`) 5개를 함께 재생하고 나가면 멈춥니다.
합계 22MB라 페이지 진입과 동시에 내려받지 않도록 한 것입니다.
모션 감소 설정에서는 재생하지 않습니다. 자동재생이 거부되면 첫 프레임에서 멈춘 채로 남습니다.

### 확인하지 못한 부분

- **화면을 눈으로 못 봤습니다.** 이번 세션도 Browser 미리보기 패널이 표시되지 않아
  캡처가 되지 않습니다. 위 검증은 전부 DOM 측정값입니다.
  **시안 스크린샷과 나란히 놓고 보는 비교는 사용자가 해야 합니다.**
- **가로 스크롤이 좁은 화면에서 해제되는지 확인 못 했습니다.**
  이 환경은 `MediaQueryList`의 `change` 이벤트를 발생시키지 않습니다
  (768 ↔ 1920으로 바꿔도 `.matches` 값은 정확히 뒤집히는데 이벤트는 0건).
  그래서 `gsap.matchMedia()`가 되돌리는 동작을 볼 수 없었습니다.
  실제 브라우저에서 창을 줄여 확인이 필요합니다.
- `requestAnimationFrame`이 돌지 않아 실제 스크롤 감각과 영상 재생은 확인 못 했습니다.
  위 가로 이동값은 `ScrollTrigger.update()`를 직접 호출해 잰 것입니다.
- 1280px 미만에서 `heritage` 제목(1385px)이 잘립니다. 반응형 작업에서 다룹니다.

## mood — 자동 인트로로 다시 만듦 (2026-08-07)

**스크롤 인터랙션에서 페이지 진입 시 저절로 재생되는 인트로로 바꿨습니다.**
가로 3패널 구조를 없애고 **고정된 무대 하나** 위에서 요소가 움직이는 방식입니다.

- 검은 화면의 초록 띠가 저절로 열리며 실내가 드러납니다.
- **사진은 그 뒤로 한 번도 움직이지 않습니다.**
- 글과 무드 패널이 오른쪽에서 차례로 들어옵니다.

이전 구조에서 지적했던 "1장면과 2장면이 같은 사진이라 같은 방이 두 번 지나간다"는
문제가 사라졌습니다. 사진이 하나뿐이고 고정이기 때문입니다.

### 이게 가능한 이유 — 세 이미지의 관계

에셋을 재보고 알아낸 사실입니다.

| 파일 | 크기 | 정체 |
|---|---|---|
| `mood_start.jpg` | 30 × 484 | `mood_inner.jpg`의 **정중앙 30px 띠와 같은 픽셀** |
| `mood_left.jpg` | 768 × 700 | 벽·그림자 근접 컷 (글 뒤에 깔림) |
| `mood_inner.jpg` | 1920 × 700 | 창문이 있는 실내 전경 |

`mood_start`와 `mood_inner` 가운데 띠의 평균색을 세로 5구간으로 비교했더니
차이가 **0~8**(최대 441)이었습니다. JPEG 압축 오차 수준으로, 같은 사진입니다.

그래서 크로스페이드가 필요 없습니다. **처음부터 `mood_inner`를 깔아 두고
보이는 창만 넓히면** 그대로 이어집니다.

### 구조

```html
<section class="mood">              <!-- 배경 검정 -->
  <div class="mood_stage">          <!-- 1920 × 700 고정 무대 -->
    <div class="mood_reveal">       <!-- 열리는 창. 이 크기를 키운다 -->
      <img class="mood_room">       <!-- 실내 전경. 무대 한가운데 고정 -->
      <img class="mood_wall">       <!-- 벽 근접 컷. 나중에 나타남 -->
      <div class="mood_copy">       <!-- 글. 오른쪽에서 들어옴 -->
      <div class="mood_words">      <!-- 올리브 패널 + 3단어. 오른쪽에서 들어옴 -->
```

#### 반드시 지켜야 하는 것

1. **`.mood_room`은 `width: 100%`가 아니라 `1920px` 고정 + 가운데 정렬입니다.**
   `100%`로 두면 창이 커질 때 사진도 같이 늘어나 그냥 확대로 보입니다.
   원본 크기로 고정해야 "가려졌던 부분이 드러나는" 느낌이 납니다.
2. **`.mood_reveal`은 `translate(-50%, -50%)`로 가운데 정렬합니다.**
   그래야 `width`/`height`만 바꿔도 중심이 안 움직입니다.
3. **CSS 기본 상태가 "다 끝난 모습"입니다.** JS가 `gsap.set`으로 시작 상태를 칠한 뒤
   재생합니다. JS나 GSAP이 없으면 완성된 화면이 그대로 보입니다(점진적 향상).
4. **`initMoodIntro()`는 `DOMContentLoaded`를 기다리지 않고 바로 실행됩니다.**
   스크립트가 body 끝에 있어 mood 마크업은 이미 파싱돼 있고, 한 프레임이라도 늦으면
   완성된 화면이 번쩍였다가 시작 상태로 돌아갑니다.
5. **`.mood_reveal`의 `overflow: hidden`이 무대 밖 요소를 가려 줍니다.**
   글과 무드 패널은 시작할 때 무대 오른쪽 바깥(x 1920)에 있습니다.

### 타임라인 (총 4.2초)

| 시점(초) | 내용 |
|---|---|
| 0 → 1.4 | 창 30×484 → 1920×700. **가로가 먼저, 세로는 0.5초 뒤에** 따라붙습니다 |
| 1.9 → 2.8 | 글이 무대 밖에서 들어와 x 1152에 안착 (시안 2장면 자리) |
| 3.1 → 4.2 | 무드 패널이 들어오며 글을 x 0으로 밀어냄 (시안 3장면 자리) |
| 3.3 → 3.8 | 글 뒤의 벽 사진이 나타남 |

글과 무드 패널은 3.1~4.2 구간에서 **같은 거리(1152px)를 함께 이동**합니다.
붙어서 밀려나는 것처럼 보이는 이유입니다.

조절값은 `js/brand.js` 상단에 있습니다.

| 상수 | 현재 | 의미 |
|---|---|---|
| `OPEN_DURATION` | 1.4초 | 문이 다 열리기까지 |
| `OPEN_HEIGHT_DELAY` | 0.5초 | 가로가 먼저 벌어지고 세로가 뒤따르는 간격 |
| `COPY_IN_AT` | 1.9초 | 글이 오른쪽에서 들어오는 시점 |
| `SHIFT_AT` | 3.1초 | 글이 왼쪽으로 밀리고 무드 패널이 들어오는 시점 |

### 같이 고친 것

- 3장면 왼쪽 배경이 `mood_start.jpg`(30×484)였습니다. Figma 내보내기 코드가
  1장면과 같은 이미지 참조를 쓰고 있었기 때문인데, 그대로 두면 30px 사진을
  768px로 25배 늘려 뭉개집니다. **`mood_left.jpg`(정확히 768×700)로 바꿨습니다** — 배율 1.00.

## mood — 문 열림 속도 조절 + 글 상자 둥둥 제거 + 버벅임 대책 (2026-08-07)

### 1) 문 열림도 조절값이 됐습니다

`▼▼ 여기 숫자만 바꾸면 됩니다 ▼▼` 블록 맨 위에 `1) 문이 열리는 속도`를 두었습니다.

| 상수 | 이전 | 지금 | 의미 |
|---|---|---|---|
| `OPEN_DURATION` | 1.4 | **2.8** | 문이 다 열리기까지(초). 키우면 느려집니다 |
| `OPEN_HEIGHT_DELAY` | 0.5 | **1** | 가로가 먼저 벌어지고 세로가 뒤따르는 간격(초) |
| `DRIFT_AT` | 1.1 | **2.4** | 띠가 흐르기 시작하는 시점(초) |
| `DRIFT_DURATION` | 8.4 | **15** (사용자가 지정) | 1920px 흐르는 시간(초) |

**`DRIFT_AT`은 `OPEN_DURATION`보다 0.3~0.5초 작게 유지해야 합니다.** 문이 다 열린 뒤에
글이 들어오기 시작하면 중간에 아무 일도 없는 빈 박자가 생깁니다. 문을 더 느리게 하면
이 값도 같이 키우세요. (JS 주석에 같은 내용을 적어 두었습니다.)

**세로 트윈 길이가 음수가 되지 않도록 잘라냅니다.** 세로 트윈은
`OPEN_DURATION − OPEN_HEIGHT_DELAY`인데, 지연을 더 크게 적으면 음수가 되어 트윈이
깨집니다. `Math.max(0.2, …)`로 막아 두었습니다.

`FLOAT_TARGETS`에서 `.mood_copy` 줄을 **주석 처리**했습니다. 지우지 않고 남겨 둔 것은
되살리기 쉽게 하려는 것입니다. 지금 흔들리는 것은 무드 단어 3개뿐입니다.

### 3) 버벅임 대책 — 원인 두 가지

#### (가) 소수점 단위 글자 이동 → `will-change: transform`

14px을 4.2초에 걸쳐 움직이면 한 프레임에 약 **0.05px**씩 갑니다. 이렇게 작은 소수점
단위로 글자가 움직이면 브라우저가 **매 프레임 글자를 다시 그립니다**(text
re-rasterization). 느리고 작은 움직임에서 아른거림·버벅임으로 보이는 전형적인 원인입니다.

`.mood_copy`, `.mood_words`, `.mood_word`에 `will-change: transform`을 넣어 미리
합성 레이어로 올렸습니다. 글자를 한 번만 그린 뒤 옮기기만 합니다.

> 대가: 합성 레이어 위의 글자는 서브픽셀 안티에일리어싱이 꺼져 아주 약간 다르게
> 보일 수 있습니다. 사진 위 글자라 오히려 자연스러운 편입니다.

#### (나) 인트로와 동시에 8MB 이미지 디코딩 → 지연 로드

이 페이지는 **이미지 24장 8.01MB를 전부 즉시 내려받고 있었습니다.** 그중 23장이
첫 화면 밖이고, PNG 5장만 5.3MB입니다. 인트로가 재생되는 바로 그 순간 브라우저가
이 이미지들을 디코딩하느라 메인 스레드를 붙잡습니다.

첫 화면 밖 **14장**(kimyoungjin 4 · atelier 7 · heritage 3)에

- **히어로 4장(`mood_inner` + 단어 사진 3장)은 건드리지 않았습니다.** 인트로가
  `mood_inner.jpg` 로드를 기다리므로 즉시 로드여야 합니다.

## mood — 배경 사진을 무대(1920 × 1080) 전체로 확대 (2026-08-07)

사용자가 `.mood_stage` 높이를 700 → **1080**으로 바꿔 위아래에 190px씩 검은 띠가
생긴 상태였습니다. **글과 사진 요소는 그대로 두고 배경 사진만** 무대를 채우게 했습니다.

### 왜 그냥 늘리면 안 되는가

원본은 1920 × 700(비율 2.743), 무대는 1920 × 1080(비율 1.778)입니다.
**비율을 지키며 높이를 채우면 1.5429배가 되어 폭이 2962px**이 되고,
**가로로 1042px이 잘립니다.** 세로는 정확히 맞아떨어져 한 픽셀도 잘리지 않습니다.

창문은 **창틀까지 원본 x 160 ~ 742**입니다(유리는 176~728). 픽셀 휘도를 열 단위로
훑어 찾은 값입니다 — x160에서 어두워지고 x162~172가 거의 검정(창틀), x176부터
0.78로 뛰어오릅니다(유리). 오른쪽은 x728에서 유리가 끝나고 x742부터 벽입니다.

확대하면 창문은 247 ~ 1145가 됩니다. 그래서 **`object-position`이 0% ~ 23.7%
사이여야 창문이 잘리지 않습니다.**

### 왜 22%인가

`object-position`을 바꾸면 글자 밑에 깔리는 사진이 달라집니다. 네 값을 재봤습니다.

| object-position | 창틀 왼쪽 화면 x | Unique(흰) | Modern(흰) | Elegant(흰) | 글 상자(검정) |
|---|---|---|---|---|---|
| 0% | 247 | **1.85** ❌ | 4.85 | 5.36 | 7.31 |
| 10% | 143 | **3.02** ❌ | 4.64 | 5.59 | 9.08 |
| **22%** | **18** | **5.15** ✅ | 3.67 | **5.76** ✅ | **10.68** |
| 23.7% | 0 (닿음) | 5.15 | 3.62 | 5.76 | 10.66 |

0%로 두면 **창문이 Unique 글자 밑으로 들어와 흰 글씨가 1.85:1**이 됩니다.
22%가 창문을 온전히 남기면서 글자 대비도 가장 좋습니다. 23.7%는 창틀이 화면
왼쪽 끝에 정확히 닿아 여유가 없습니다.

**Modern은 3.67:1로 여전히 미달이지만 이전(2.98:1)보다는 나아졌습니다.**
원래 있던 문제이고 처리 방향은 아직 미정입니다(아래 "다음 작업" 1번).

### 구현

CSS 변수 두 개로 정리했습니다. 다른 값은 전부 여기서 따라옵니다.

```css
.mood {
  --mood_stage_h: 1080px;   /* 무대 높이. 문과 배경이 따라옵니다 */
  --mood_room_pos: 22%;     /* ★ 배경 사진 가로 위치. 0% ~ 23.7%만 유효 */
}
```

- `.mood_reveal`, `.mood_room` 모두 높이를 `var(--mood_stage_h)`로 받습니다.
- `.mood_room`은 상자를 무대와 같은 1920 × 1080으로 잡고 **`object-fit: cover`에
  맡깁니다.** 비율은 브라우저가 지키므로 찌그러지지 않고, 잘리는 쪽의 위치만
  `object-position: var(--mood_room_pos) center`로 정합니다.
- **`.mood_copy` / `.mood_words` / `.mood_word_*`는 한 줄도 건드리지 않았습니다.**

#### ⚠ JS가 CSS를 덮어쓰고 있었습니다

`.mood_reveal`의 CSS 높이를 1080으로 바꿔도 **문은 700에서 멈춥니다.**
`js/brand.js`가 `STAGE_HEIGHT`(700)로 height를 트윈하면서 남기는 **인라인 style이
CSS를 이기기 때문입니다.** 배경을 아무리 키워도 700 위쪽만 보였을 것입니다.

고친 방식: 숫자를 JS에 또 적지 않고 **재생할 때 `.mood_stage`의 실제 높이를 DOM에서
읽습니다.** CSS가 유일한 기준이 되어 둘이 어긋날 수 없습니다.

```js
var stageHeight = (stage && Math.round(stage.getBoundingClientRect().height)) || STAGE_HEIGHT;
```

`STAGE_HEIGHT`(1080)는 못 읽었을 때만 쓰는 대비값으로 남겼습니다.

## mood — 무대 1920 × 1080 고정 + 배경 이미지 교체 규격 (2026-08-07)

사용자가 **배경을 여백까지 넣은 이미지로 직접 만들어 끼우기로** 해서, 무대 크기를
고정하고 교체 규격을 정리했습니다.

### 고정된 값

```css
.mood {
  --mood_stage_w: 1920px;   /* 무대 폭 */
  --mood_stage_h: 1080px;   /* 무대 높이 = 섹션 높이 */
}
```

`.mood_stage` / `.mood_reveal` / `.mood_room` 세 곳이 전부 이 변수를 받습니다.
`js/brand.js`도 문이 다 열린 높이를 `.mood_stage`에서 직접 읽으므로,
**여기 두 줄만 바꾸면 전부 따라옵니다.**

섹션 높이는 이 무대 하나가 정합니다 — `.mood`에 padding·margin이 없습니다.

### 배경 이미지 교체 규격

**1920 × 1080으로 만들어 `index.html`의 `.mood_room` 한 줄만 바꾸면 됩니다.
CSS는 손댈 필요 없습니다.**

```html
<img class="mood_room" src="assets/images/(새 파일)" alt="" aria-hidden="true">
```

- 상자가 1920 × 1080이라 같은 크기 이미지는 **배율 1.0, 가로 잘림 0, 세로 잘림 0**으로
  1:1로 그려집니다(계산 확인).
- 그때는 **`--mood_room_pos` 값이 아무 영향을 주지 않습니다.** 넘치는 부분이 없기
  때문입니다. 22%든 50%든 결과가 같으니 그대로 두면 됩니다.
- 이미지 안에 넣을 여백(레터박스) 색은 `--brand_black`(**#120f0f**)에 맞추면
  섹션 배경과 이어져 보입니다.
- 크기가 다른 이미지를 넣어도 깨지지 않습니다. `object-fit: cover`가 비율을 지키며
  채우고 남는 쪽이 잘리며, 잘리는 위치는 `--mood_room_pos`가 정합니다.

### 좁은 화면에서의 동작

`.mood_stage`는 `width: var(--mood_stage_w)` + `margin-left: calc(50% - var(--mood_stage_w) / 2)`입니다.
화면이 1920보다 좁으면 **좌우가 똑같이** 잘립니다(`.mood`의 `overflow-x: clip`).
`margin-inline: auto`는 왼쪽으로 붙어 좌우가 비대칭으로 잘리므로 쓰지 않습니다.

| 화면 폭 | margin-left | 좌우 각각 잘리는 양 |
|---|---|---|
| 1280px | −320px | 320px |
| 1600px | −160px | 160px |
| 1920px | 0 | 0 |
| 2560px | +320px | 잘리지 않고 가운데 정렬 |

**높이는 폭과 무관하게 항상 1080px입니다.**

### 검증 결과 (2026-08-07, 1920 × 1080, localhost:5611)

- 섹션 높이 정확히 **1080px**, padding·margin 0, **다음 섹션(`.kimyoungjin`)이 y=1080에서 시작.**
- `.mood_stage` / `.mood_reveal`(인트로 후) / `.mood_room` 모두 **1920 × 1080**.
- 변수 계산값: `--mood_stage_w: 1920px`, `--mood_stage_h: 1080px`, `--mood_room_pos: 22%`.
- **1920 × 1080 이미지를 넣을 경우 시뮬레이션**: 배율 1.0, 그려지는 크기 1920×1080,
  가로 잘림 **0**, 세로 잘림 **0** → `object-position` 무관.
- 배경 고정 유지 — 서로 다른 상태 1개
  (`0|0|1920|1080|cover|22% 50%|matrix(1,0,0,1,-960,-540)`).
- 페이지 높이 19329px, ScrollTrigger 1개, 가로 스크롤 0.
- 실패 요청 0, 깨진 이미지 0, 콘솔 오류 없음.
- 문법·구조: JS `new Function()` 통과, CSS 중괄호 62/62, 파싱 규칙 62개 중
  선언 없는 규칙 0개.
