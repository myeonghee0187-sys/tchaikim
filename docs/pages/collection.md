### 0. 에셋 정리

다운로드할 때 붙은 접미사를 떼어 규칙을 맞췄습니다. 이름만 바꿨고 내용은 그대로입니다.

```
archive_2019_1 1.png  →  archive_2019_1.png
...
archive_2021_5 1.png  →  archive_2021_5.png   (총 15개)
```

연도별로 정확히 5장씩 있는 것을 확인했습니다. 원본 크기와 비율:

| 파일 | 크기 | 비율 | 용량 |
|---|---|---|---|
| archive_2019_1~5 | 3263 × 4898 | 0.666 (세로) | 5.3 ~ 11.9 MB |
| archive_2020_1~3, _5 | 3336 × 5008 | 0.666 (세로) | 6.9 ~ 9.8 MB |
| archive_2020_4 | 3704 × 5559 | 0.666 (세로) | 15.2 MB |
| archive_2021_1 | 4898 × 3259 | **1.503 (가로)** | 14.2 MB |
| archive_2021_2 | 3266 × 4898 | 0.667 (세로) | 13.2 MB |
| archive_2021_3~5 | 3347 × 4730 | 0.708 (세로) | 13.8 ~ 17.5 MB |

**15장 합계가 약 159MB입니다.** 한 연도만 봐도 2019 37.6MB / 2020 48.2MB / 2021 73.6MB를
내려받습니다. 화면 표시 폭은 380 ~ 672px인데 원본은 3263 ~ 4898px이라 7~10배 큽니다.
사용자가 준 원본이라 이번 작업에서는 손대지 않았습니다.
**배포 전에 표시 폭의 2배(약 1400px) 정도로 리사이즈하는 작업이 따로 필요합니다.**
`collection_film.mp4`를 만들 때 쓴 ffmpeg가 이미 설치돼 있습니다.

### 1. 연도별 사진 데이터

`collection.js` 상단의 `ARCHIVE_PHOTOS`에 2019 / 2020 / 2021 세 세트를 두었습니다.
배열 순서가 곧 슬롯(`.archive_photo_1` ~ `_5`) 순서이자 쌓이는 순서입니다.

```js
{ src: "/asset/collection/archive_2019_1.png", width: 3263, height: 4898, alt: "..." }
```

`width` / `height`는 원본 픽셀 크기입니다. 두 가지에 씁니다.

1. 가로형 판별 — `width > height`이면 `is_wide` class를 붙입니다.
2. 로딩 전 자리 확보 — `img`의 `width` / `height` 속성이 되어 브라우저가
   내려받기 전에도 원본 비율만큼 높이를 잡아 둡니다.

**2021은 파일 번호 순서가 아닙니다.** `archive_2021_1`이 15장 중 유일한 가로형이라
가장 넓은 3번 슬롯에 두었습니다(`2021_2, 2021_3, 2021_1, 2021_4, 2021_5`).
좁은 슬롯에 넣으면 그 카드만 눈에 띄게 작아 보입니다.

2013 / 2015 / 2017 / 2018은 연결할 사진이 없어 데이터에 없고, HTML도 기존 정적 링크 그대로입니다.

### 2. 겹쳐 쌓이는 레이아웃

**높이를 지정하지 않습니다.** 슬롯마다 정하는 것은 `left` / `top` / 폭 / 기울기 / 쌓임 순서뿐이고,
높이는 `img`가 원본 비율대로 결정합니다(`width: 100%; height: auto`).
연도마다 비율이 달라(0.666 / 0.708 / 1.503) 높이를 고정하면 잘라내야 하기 때문입니다.
그래서 기존의 `height` + `object-fit: cover` 조합을 걷어냈습니다.

슬롯 값은 CSS 커스텀 속성으로 슬롯 class 안에 모아 두었습니다.

| 슬롯 | left | top | 폭 | 기울기 | z-index |
|---|---|---|---|---|---|
| `_1` | 620 | 150 | 470 | -3.2° | 1 |
| `_2` | 1040 | 60 | 380 | 2.6° | 2 |
| `_3` | 900 | 560 | 560 | -1.4° | 3 |
| `_4` | 560 | 860 | 400 | 3.8° | 4 |
| `_5` | 1310 | 1000 | 430 | -2.6° | 5 |

- 왼쪽 sticky 글 영역이 x 120 ~ 470을 쓰므로 사진은 x 560부터 시작합니다.
- `.archive_photo.is_wide`는 슬롯 폭의 1.2배를 씁니다(3번 슬롯 560 → 672).
- 겹친 사진끼리 경계가 보이도록 `padding: 10px` + `--color_bg` 배경으로 여백을 두르고
  그림자를 깔았습니다. 여백이 없으면 사진 두 장이 한 장처럼 붙어 보입니다.

### 3. 등장 애니메이션

showcase 하단 갤러리와 같은 `fromTo(y + opacity)`를 씁니다.
카드마다 출발 거리를 다르게 줘야(`RISE_BASE + index * RISE_STEP`) 한 덩어리로 밀려 올라오지 않고
따로 얹힙니다. 여기에 `scale 0.92 → 1`을 더해 뒤에서 앞으로 오는 느낌을 줬습니다.

**다른 점: 카드마다 트리거를 달지 않고 타임라인 하나에 `stagger`로 묶었습니다.**
연도를 바꿀 때 처음부터 다시 재생해야 하는데, showcase가 쓰는 `scrub` 트리거는
값이 스크롤 위치에 묶여 있어 프로그램에서 다시 재생할 수 없기 때문입니다.
대신 `toggleActions: "play none none none"`으로 한 번 재생하고, 그 뒤로는 스크롤이
값을 건드리지 않아 `restart()`로 다시 쓸 수 있습니다.

조절값은 `js/collection.js` 상단 `archive 조절값` 블록에 모여 있습니다.

| 상수 | 현재 | 의미 |
|---|---|---|
| `ARCHIVE_RISE_BASE` / `_STEP` | 90 / 18 | 떠오르는 거리와 카드별 증가폭 |
| `ARCHIVE_ENTER_SCALE` | 0.92 | 출발 배율 |
| `ARCHIVE_DURATION` / `_STAGGER` | 0.85 / 0.16 | 한 장이 올라오는 시간 / 장 사이 간격 |
| `ARCHIVE_SWAP_FADE` | 0.25 | 연도 전환 때 이전 세트가 사라지는 시간 |
| `ARCHIVE_START` | `"top top+=25%"` | 쌓기 시작하는 스크롤 지점 |

#### 반드시 지켜야 하는 것

**`gsap.set(images, archiveEnterVars())`를 지우면 안 됩니다.**
`stagger`를 건 `fromTo`는 각 대상의 차례가 와야 from 값을 적용합니다.
미리 넣어 두지 않으면 두 번째 사진부터는 트리거 전까지 그대로 보이다가
자기 차례에 갑자기 사라졌다 다시 나타납니다. 실제로 이 증상이 났고,
opacity가 `[0, 1, 1, 1, 1]`인 것을 확인한 뒤 고쳤습니다.
`archiveEnterVars()`가 `gsap.set`과 `fromTo`의 from 값을 한 곳에서 만들므로 둘은 항상 같습니다.

- **`.archive_sticky` 높이를 `100%`로.** 프레임 높이를 바꿀 때마다 같이 고쳐야 하는 값을 없앴습니다.
  padding-top은 347 → 200px입니다.
- **연도 2019 / 2020 / 2021은 `a`가 아니라 `button`.**
  페이지 이동이 아니라 오른쪽 갤러리를 바꾸는 동작이라 `AGENTS.md`의
  "동작은 button, 페이지 이동은 a" 규칙을 따랐습니다.
  같은 이유로 감싸던 `nav`는 `div` + `role="group"`으로 바꿨습니다(내비게이션이 아니라 필터입니다).
  데이터가 없는 나머지 4개는 요청대로 기존 `a href="#"` 그대로 두었습니다.
- **2013 / 2015 / 2017 / 2018을 눌러도 아무 일도 일어나지 않습니다.**
  활성 표시만 옮기면 "2013을 골랐는데 2019 사진이 보이는" 상태가 되어 더 혼란스럽습니다.
- **사진에 `loading="lazy"` 추가.** archive는 문서 5917px 아래라 첫 화면에 필요 없는데
  한 세트가 37 ~ 74MB입니다. 스크롤이 가까워질 때 받도록 했습니다.
- **hover 그림자.** 시안에 없는 요소지만, 카드가 겹쳐 있어서 크기 변화만으로는
  "맨 앞으로 올라왔다"가 읽히지 않습니다.
- **z-index 복귀에만 transition-delay.** `transition: z-index 0s var(--duration_base)`를
  기본 상태에 두고 hover 상태에서는 `0s`로 덮습니다. 이렇게 해야 마우스를 뗀 뒤
  카드가 작아지는 0.4초 동안 맨 위에 남아 있다가 제자리 순서로 돌아갑니다.

## archive 섹션 2차 — 날아드는 등장 / 액자 제거 / 연도별 배치 (2026-08-06)

위 1차 작업에 이어 네 가지를 고쳤습니다.

### 변경 파일

- `pages/collection_test/index.html` — 기본 연도 2019 → 2021 (활성 표시 + 사진 5장)
- `pages/collection_test/css/collection.css` — 액자 스타일 제거, 배치를 커스텀 속성으로, `overflow: clip`
- `pages/collection_test/js/collection.js` — `ARCHIVE_LAYOUTS` 신설, 날아드는 등장으로 교체

### 1. 등장 — 각자 다른 방향·거리에서 날아 들어옴

이전에는 다섯 장이 모두 아래에서 위로만(`y: 90 ~ 162`) 떠올랐습니다.
지금은 showcase 상단 두 장이 화면 양 끝에서 날아 들어오는 것과 같은 방식으로,
카드마다 **다른 방향, 다른 거리, 다른 회전**에서 출발합니다.

**방향은 하드코딩이 아니라 좌표에서 계산합니다.** 카드 중심이 1920 캔버스 중앙의
어느 쪽에 있는지로 방향을 정하고, 길이를 1로 맞춘 뒤 거리를 따로 곱합니다
(`enterDirection()`). 길이를 맞추지 않으면 중앙에 가까운 카드는 거의 제자리에서 나타납니다.
좌표를 바꾸면 날아오는 방향도 알아서 따라옵니다 — showcase의 `convergeDistance`와 같은 생각입니다.

거리 배수(`travel`)와 회전은 카드마다 다릅니다. 회전은 출발 방향의 좌우 성분에
`ARCHIVE_ENTER_SPIN`을 곱해 얻으므로, 오른쪽에서 오는 카드와 왼쪽에서 오는 카드가 반대로 기울어집니다.

showcase와 같은 점: figure는 가만히 두고 안쪽 `img`만 움직입니다.
다른 점: 카드마다 트리거를 달지 않고 타임라인 하나에 `stagger`로 묶습니다
(연도 전환 때 `restart()`로 다시 재생해야 하는데 `scrub` 트리거는 그럴 수 없습니다).

| 상수 | 현재 | 의미 |
|---|---|---|
| `ARCHIVE_ENTER_DISTANCE` | 520 | 기본 출발 거리. 카드별 `travel` 배수를 곱합니다 |
| `ARCHIVE_ENTER_SCALE` | 0.78 | 출발 배율 |
| `ARCHIVE_ENTER_SPIN` | 14 | 출발 회전각(deg). 방향의 좌우 성분에 곱합니다 |
| `ARCHIVE_DURATION` / `_STAGGER` | 0.95 / 0.18 | 한 장이 날아드는 시간 / 장 사이 간격 |

**`filter: blur()`는 넣지 않았습니다.** showcase 상단 두 장은 blur를 쓰지만
그건 사진 두 장짜리 scrub 연출이고, 여기는 3000px대 원본 다섯 장이 동시에 움직입니다.
참고 대상인 showcase 하단 갤러리(`_c ~ _g`)도 blur 없이 y와 opacity만 씁니다.

### 2. 흰 액자 제거

`.archive_photo`에서 `padding: 10px` / `background-color` / 기본 `box-shadow`를 모두 뺐습니다.
이미지 자체만 떠 있습니다. 그림자는 **hover 상태에만** 남겼습니다.
평소에도 두면 사진마다 사각 윤곽이 생겨 지우기로 한 액자와 같은 인상이 됩니다.
평상시 그림자까지 없애려면 `.archive_photo:hover`의 `box-shadow` 한 줄만 지우면 됩니다.

### 3. 기본 진입 연도 2021

`ARCHIVE_DEFAULT_YEAR = "2021"`. HTML의 사진 5장과 활성 표시(`is_active`, `aria-current`)도
2021로 옮겼습니다. HTML의 사진 순서는 `ARCHIVE_PHOTOS["2021"]`와 같아야 합니다
(파일 번호 순서가 아닙니다 — 유일한 가로형 `archive_2021_1`이 3번 자리입니다).

### 4. 연도마다 다른 배치

배치는 `collection.js`의 `ARCHIVE_LAYOUTS`로 옮겼습니다.
연도마다 다섯 자리 전부가 다릅니다 — 위치·폭·기울기·겹침 순서·출발 거리.
격자나 대각선 같은 규칙 없이 손으로 흩어 놓은 값이고, `layer`(z-index)는 1~5를
순서 없이 섞어 어느 카드가 위로 올지 예측되지 않게 했습니다.

기울기와 z-index는 지금도 이 값입니다. **위치와 폭은 아래
"화면 한 장에 맞추기"에서 다시 줄었습니다** — 최신 값은 그쪽 표를 보세요.

| 연도 | 폭(px) | 기울기(deg) | z-index | 차지하는 범위 |
|---|---|---|---|---|
| 2021 | ~~620 / 360 / 540 / 470 / 300~~ | -4.5 / 6.2 / -2.1 / 3.4 / -7.8 | 2 / 5 / 1 / 4 / 3 | ~~y 60~1504~~ |
| 2020 | ~~400 / 560 / 320 / 640 / 430~~ | 5.6 / -3.1 / 8.4 / -1.8 / 4.2 | 3 / 1 / 5 / 2 / 4 | ~~y 90~1661~~ |
| 2019 | ~~300 / 480 / 600 / 380 / 520~~ | -6.8 / 2.4 / -1.2 / 7.1 / -4.6 | 4 / 2 / 3 / 5 / 1 | ~~y 80~1581~~ |

새 배치를 만들 때 지킬 것 두 가지입니다.

1. 왼쪽 sticky 글 영역이 x 120~470을 쓰므로 `left`는 500 이상이어야 합니다.
2. 오른쪽 끝 1780 이하, 아래 끝 1800(프레임 높이) 이하. 벗어나면 `overflow: clip`에 잘립니다.

배치를 바꿀 때 **CSS와 JS 두 곳을 함께 고쳐야 합니다.**
`collection.css`의 `.archive_photo_1 ~ _5`는 JS가 꺼져 있을 때 보이는 기본값이자 2021 배치이고,
`ARCHIVE_LAYOUTS["2021"]`과 같은 값이어야 합니다. 나머지 두 연도는 JS에만 있습니다.

#### 이 구조에서 반드시 지켜야 하는 것

1. **`timeline.invalidate().restart()`** — `invalidate()`가 없으면 GSAP이 기록해 둔 시작값이
   첫 연도 배치 그대로 굳어, 연도를 바꿔도 이전 배치 기준 방향으로 날아옵니다.
2. **`.archive`는 `overflow-x: clip`이 아니라 `overflow: clip`입니다.**
   카드가 위아래로도 화면 밖에서 출발하므로 x만 자르면 출발 위치의 카드가
   위쪽 showcase / 아래쪽 asworn 섹션 위에 겹쳐 보입니다.
   `hidden`이 아니라 `clip`이어야 하는 이유는 1차 작업과 같습니다(sticky가 죽습니다).
3. **날아오는 방향 계산에는 `img.naturalHeight`가 아니라 `ARCHIVE_PHOTOS`의 원본 크기를 씁니다.**
   사진이 `loading="lazy"`라 첫 계산 시점에 `naturalHeight`가 0입니다.
   그대로 두면 카드 중심을 잘못 잡아 가로형 사진의 출발 방향이 틀어집니다(실제로 그랬습니다).

## 화면 한 장에 맞추기 — 문장 잘림 / 카드 크기 (2026-08-06)

사용자 화면은 **1920 × 1080, 배율 100%**입니다. 브라우저 주소창·탭·작업표시줄을 빼면
실제 보이는 높이는 **약 948px**입니다. 시안(1920 × 1080 캔버스)은 이 여백을 계산하지 않아
두 곳이 화면 밖으로 나갔습니다.

### 1. showcase 문장이 잘리던 문제

`.showcase_quote`는 시안 좌표대로 `top: 712px`, 높이 311px이라 아래 끝이 **1023px**이었습니다.
showcase는 pin 구간에서 화면 높이만큼만 보이므로 948px 화면에서는 세 번째 줄
"Ordinary Fashion"이 잘렸습니다.

```css
top: min(712px, calc(100vh - 360px));
```

화면이 충분히 높으면 시안 값을 그대로 쓰고, 낮으면 세 줄 전체가 들어오도록 위로 올립니다.
360px은 블록 높이 311 + 아래 여백 49입니다. 좌우 위치와 줄 간격은 시안 그대로 두었습니다.

| 화면 높이 | 문장 위치 | 결과 |
|---|---|---|
| 1080 | 712 → 1023 | 시안 값 그대로 |
| 948 (사용자 환경) | 588 → 899 | 아래 49px 여유 |
| 800 | 440 → 751 | 아래 49px 여유 |

### 2. archive 카드 5장이 한 화면에 안 들어오던 문제

카드가 세로 1661px에 걸쳐 있어 한 화면에 두세 장만 보였습니다.
**프레임 높이를 1800 → 920px으로 줄이고 카드 폭도 함께 줄여** 다섯 장이 y 40~838 안에 들어옵니다.

- `.archive_frame { height: 920px }`
- `.archive_sticky` padding-top 200 → 130px (짧아진 섹션 안에서 글 영역이 가운데에 오도록)
- `ARCHIVE_START` `"top top+=25%"` → `"top top+=10%"`
  (섹션이 화면 한 장 정도라 25%면 아래쪽 카드가 아직 화면 밖일 때 시작합니다)

카드 폭도 절반 가까이 줄었습니다. **폭을 키우면 높이가 원본 비율만큼 따라 커집니다**
(세로 사진 높이 = 폭 × 1.5, 가로 사진 = 폭 × 0.67). 새 배치 표는 다음과 같습니다.

| 연도 | 폭(px) | 차지하는 범위 | 아래 끝 |
|---|---|---|---|
| 2021 | 330 / 240 / 480 / 300 / 260 | x 530~1640 | 824 |
| 2020 | 250 / 340 / 200 / 390 / 270 | x 560~1550 | 825 |
| 2019 | 190 / 300 / 370 / 260 / 330 | x 540~1660 | 826 |

**이 배치는 화면 높이 약 830px 이상을 전제합니다.** 그보다 낮으면 아래쪽 카드가 잘립니다
(800px 화면에서 24px 모자랍니다). 더 낮은 화면까지 맞추려면 폭을 더 줄여야 합니다.

### 3. 연도 전환이 빈 화면으로 끝나던 버그

작업 중 발견해 고쳤습니다. **연도를 바꾸면 사진이 다시 나타나지 않고 `opacity: 0`에 멈췄습니다.**
타임라인 `progress`는 1까지 갔는데 화면은 비어 있었습니다.

원인은 연도 전환 fade 트윈의 **`overwrite: true`**였습니다.
GSAP의 overwrite는 같은 대상의 다른 트윈을 죽이는데, 그 "다른 트윈"에
타임라인 안의 등장 트윈까지 포함됩니다. 한 번 죽으면 `restart()`가 타임라인만 진행시킬 뿐
사진에는 아무 값도 쓰지 않습니다.

```js
if (fadeTween) { fadeTween.kill(); }   // 연달아 누를 때의 중복은 이렇게 막습니다
timeline.pause();
fadeTween = gsap.to(images, { opacity: 0, /* overwrite 없음 */ … });
```

연달아 4번(2021 → 2020 → 2019 → 2021) 80ms 간격으로 눌러도 마지막에 누른 연도로
정확히 정리되는 것을 확인했습니다.

### 검증 결과 (2026-08-06, 1878 × 948 — 사용자 환경과 같은 조건)

- 문장 세 줄이 모두 화면 안 — `You Won't` 588~670 / `Find This in` 705~787 /
  `Ordinary Fashion` 817~899, 단어 7개 opacity 전부 1. 화면 캡처로도 확인.
- archive 카드 5장이 세 연도 모두 **한 화면에 전부** 들어옴
  (`getBoundingClientRect`가 0 ≤ top, bottom ≤ 948, 0 ≤ left, right ≤ 1878).
  아래 끝 2021 832 / 2020 835 / 2019 838.
- 가려짐 정도(4px 격자): 2021 `82.7 / 100 / 85.1 / 100 / 100`,
  2020 `94.3 / 57.6 / 100 / 80 / 100`, 2019 `100 / 98.2 / 81 / 100 / 90.4`.
  가장 많이 가려지는 카드도 57.6%가 보입니다.
- 연도 전환 3종 모두 사진·배치·활성 표시가 정확히 바뀌고 opacity 1로 복귀. 세 연도 화면 캡처 확인.
- 문장 위치를 1080 / 948 / 800 세 높이에서 확인 — 위 표와 일치.
- 가로 스크롤 0, 페이지 높이 9154px(이전 10107px), 트리거 7개, 4xx 응답 0건.
- 1024px 창(새로 열었을 때): 트리거 0개, pin-spacer 없음, 가로 스크롤 0,
  사진 `opacity 1` / `transform: none`, 연도 전환은 애니메이션 없이 즉시 교체.

### 확인하지 못한 부분 / 알아 둘 것

- **창 크기를 계속 바꾸는 도중에는** showcase pin이 만든 `pin-spacer`(1920 폭)가 남아

### GSAP / ScrollTrigger

이미 페이지가 gsap 3.13.0 + ScrollTrigger + Lenis를 CDN으로 불러오고 있고
`common.js`가 Lenis를 GSAP 티커·ScrollTrigger에 연결해 둡니다. **새로 추가한
라이브러리는 없습니다.** 기존 구조를 그대로 쓰되 `pin` + `scrub`으로 바꿨습니다.

### showcase — pin + 계단식 이동

섹션이 화면보다 3배 커서 통째로 pin할 수 없습니다. 대신:

1. `.showcase.is_pinned`가 **섹션을 화면 한 장 크기(`height: 100vh`)로 줄여 "창"으로**
   씁니다. 안쪽 배경과 프레임은 3335px 그대로 남아 `overflow: hidden`에 잘립니다.
2. 그 창을 `pin: true`로 고정하고, `scrub: 1`로 **배경(`.showcase_bg`)과
   프레임(`.showcase_frame`) 두 겹을 함께** 밀어 올립니다.
3. 타임라인이 **이동과 등장을 번갈아** 놓습니다. 카드가 뜨는 구간에는 이동 트윈이
   아예 없어 프레임이 1px도 움직이지 않습니다.

```
인트로(2.95) → 이동 → 카드 c 등장 → 이동 → 카드 d 등장 → … → 바닥까지 이동 → 머묾
```

- **배경도 같이 밀어야 합니다.** 프레임만 밀면 사진이 그라디언트 위를 미끄러져
  시안의 색 배치가 어긋납니다.
- **멈추는 위치는 하드코딩이 아닙니다.** `galleryStops()`가 "카드 중심이 화면 중심에
  오는 지점"을 계산해 0~travel로 자릅니다. **누적 최댓값으로 단조 증가시키는 것이
  중요합니다** — 시안에서 d의 중심이 c보다 59px 위에 있어서, 그대로 쓰면 스크롤을
  내리는데 프레임이 되올라갑니다.
- **pin 길이를 화면 배수로 적지 않습니다.** `타임라인 길이 × SHOWCASE_PX_PER_UNIT`으로
  냅니다. 예전 방식은 구간을 하나 더하면 전체 속도가 같이 바뀌었습니다.

### archive — 프레임 통째로 pin

프레임이 920px으로 화면(1080px)보다 작아서 **그대로 pin하면 됩니다.**
`start: "center center"`라 프레임이 화면 한가운데(top 80 / bottom 1000)에 멈춥니다.

- `toggleActions` → `pin: true` + `scrub: 1`. 스크롤 진행도가 곧 등장 진행도입니다.
- `ARCHIVE_STAGGER`를 0.18 → **0.5**로 올렸습니다(DURATION 0.95 → 0.75).
  예전 값은 겹침이 커서 다섯 장이 거의 동시에 들어왔습니다. 이제 한 장씩 보입니다.
- 마지막에 빈 트윈(`ARCHIVE_HOLD`)을 붙여 다섯 장이 다 놓인 화면을 읽을 시간을 둡니다.

#### ★ 연도 전환과 scrub의 충돌 (반드시 알아 둘 것)

`scrub` 타임라인은 값이 스크롤 위치에 묶여 있어 **`restart()`로 다시 재생할 수
없습니다.** 예전 코드의 `timeline.invalidate().restart()`가 그래서 못 쓰게 됐습니다.

지금은 이렇게 나눴습니다.

1. 스크롤 등장 → scrub 타임라인
2. 연도 전환 다시보기 → `archiveReplay`라는 **별도 트윈** (`ARCHIVE_REPLAY_*` 상수)
3. 둘이 같은 값을 서로 덮어쓰지 않도록, ScrollTrigger의 `onUpdate`가
   **스크롤이 들어오는 순간 `archiveReplay`를 kill합니다.** 스크롤 쪽을 진실로
   삼는 것이고, 스크롤이 정하는 값은 언제나 올바른 상태라 화면이 튀지 않습니다.

`timeline.pause()`는 제거했습니다. scrub 타임라인을 pause하면 스크롤이 먹지 않습니다.

### 창 크기 변화

카드가 멈추는 위치와 이동 거리는 창 높이에서 나오는데, 그 값이 **타임라인의 길이까지**
정합니다. 길이는 함수로 줄 수 없어서 `invalidateOnRefresh`로는 따라잡히지 않습니다.
그래서 `createRebuilder()`가 창이 실제로 달라졌을 때(`REBUILD_TOLERANCE` 40px)
`gsap.matchMedia()`를 통째로 새로 만듭니다. 디바운스 200ms입니다.

### 조절값

전부 파일 맨 위 한 블록에 주석과 함께 있습니다.

| 상수 | 값 | 의미 |
|---|---|---|
| `SHOWCASE_PX_PER_UNIT` | 512 | 타임라인 1단위 = 몇 px 스크롤. 올리면 전 구간이 느려집니다 |
| `GALLERY_HOLD` | 0.9 | 카드 한 장이 등장하는 동안 프레임이 멈춰 있는 길이 |

### 확인하지 못한 부분 / 추후 주의사항

- **스크롤된 상태의 화면 캡처를 못 했습니다.** 이 세션의 미리보기 패널은
  `document.hidden`이 `true`라 `requestAnimationFrame`이 돌지 않고, 첫 화면 말고는
  다시 그리지 않습니다(캡처하면 빈 크림색). 위 수치는 전부 `scrollTo()` +
  `ScrollTrigger.update()` 뒤의 `getBoundingClientRect()` / `getComputedStyle()`
  측정입니다. **실제 스크롤 감각, 이동과 등장의 리듬, 마우스 hover는 사용자가
  직접 봐야 합니다.**
- **showcase는 "카드가 뜨는 동안"만 고정입니다.** 카드가 다 뜬 뒤 다음 카드로 가는
  이동 구간에서는 앞 카드가 위로 지나갑니다. 섹션이 3335px이라 다섯 장을 한 화면에
  동시에 둘 수 없어서 그렇습니다(카드 c 혼자 959px). 시안 배치를 바꾸지 않는 한
  피할 수 없는 부분이고, 사용자가 지적한 "등장 중 잘림"과는 다른 현상입니다.
- **화면 높이가 830px 미만이면** archive 프레임(920px)이 화면보다 커져 pin해도
  잘립니다. 기존 제약 그대로입니다.
- **창 크기를 바꾸면 pin이 잠깐 사라졌다 다시 생깁니다**(`createRebuilder`).
  그 순간 스크롤 위치가 조금 튈 수 있습니다.
- 히어로 영상이 여전히 404입니다(`asset/`에 mp4가 없습니다). **기존 문제이고
  이번 수정과 무관합니다** — HTML은 건드리지 않았습니다.
- `prefers-reduced-motion: reduce` 환경의 실제 동작은 실행해 보지 못했습니다
  (`gsap.matchMedia()`가 위 1280px 미만과 같은 경로로 되돌리도록 작성).

#### 멈춤의 정확한 위치 (측정)

| 위치 | 정지 거리 | 그 사이에 일어나는 일 |
|---|---|---|
| 상단 두 장 안착 → 퇴장 시작 | **241px** | 없음(단어는 이미 다 떴음) |
| 인트로 끝 → 첫 갤러리 카드 | **1194px** | 배경만 미끄러짐 |

#### 고친 방법

**① 이동 구간을 짧게.** `GALLERY_TRAVEL_SPEED` 512 → **880**.
이동에 쓰는 스크롤이 실제 이동 거리의 약 43%로 줄어, 카드 없는 구간이 짧아집니다.

**② 이동과 등장을 겹칩니다.** `GALLERY_LEAD`(0.3) 신설 — 이동이 끝나기 전에 등장이
시작됩니다. "이동 → 딱 멈춤 → 등장"의 이음매가 사라집니다.
**위쪽 잘림은 여전히 구조적으로 불가능합니다** — 프레임은 위로 올라가는 중이라
카드는 늘 아래에서 올라오고, 이동이 끝나는 지점이 곧 카드가 화면 한가운데에 서는
자리이며 그 뒤로는 프레임이 멈춰 있기 때문입니다.
`lead`는 `Math.min(GALLERY_LEAD, moveLength)`로 자릅니다. 이동보다 길면 앞 카드의
등장 구간을 침범합니다(e·g는 이동이 짧아 실제로 잘립니다).

**③ 인트로와 갤러리를 겹칩니다.** `INTRO_HANDOFF`(0.75) 신설 —
상단 두 장이 물러나는 동안 프레임이 이미 움직이기 시작합니다.

**④ 두 장이 뜬 뒤의 정지 제거.** `EXIT_START` 1.55 → **1.2**
(B가 안착하는 1.08의 바로 뒤), `EXIT_DURATION` 1.4 → **1.15**.

**⑤ 전체 속도.** `SHOWCASE_PX_PER_UNIT` 512 → **380**,
`GALLERY_HOLD` 0.9 → **0.62**, `SHOWCASE_TAIL_HOLD` 0.4 → **0.25**,

archive는 `ARCHIVE_PX_PER_UNIT` 520 → **400**, `ARCHIVE_STAGGER` 0.5 → **0.42**,
`ARCHIVE_HOLD` 0.7 → **0.45**.

### ★ 스크롤이 뚝뚝 끊기던 문제 (2026-08-08, 3차)

사용자 지적: **"카드 등장부터 갑자기 스크롤이 뚝뚝 끊기는 느낌."**

#### 원인 — 이동 속도가 사각파였습니다

스크롤 1px당 프레임이 몇 px 움직이는지(= 평소 스크롤 대비 배속)를 pin 전 구간에서
20px 간격으로 재 봤습니다.

```
0-600    : 0x      ← 인트로(프레임 정지)
620-1120 : 2.32x   ← 갑자기 2.32배
1120-1480: 0.19x   ← 다시 정지 (360px)
1480-1560: 2.32x
1560-1700: 0.08x
1720-1900: 2.32x
1920-2020: 0x
2040-2120: 2.32x
2120-2260: 0x
2280-2360: 2.32x
2360-2440: 0x
```

- pin 2454px 중 **1360px(55%)이 완전 정지**
- `ease: "none"`이라 속도가 **0 ↔ 2.32 사이를 즉시** 오감 (이음매 10곳)

2차에서 "카드 없는 이동 구간이 길다"는 문제를 `GALLERY_TRAVEL_SPEED`를 880으로
올려 해결했는데, 그 결과 이동 구간이 **평소 스크롤의 2.32배**로 몰아치게 됐습니다.
정지 구간이 많을수록 남은 구간이 빨라져야 하므로 둘은 같은 문제의 양면입니다.

**끊김은 속도의 크기가 아니라 속도가 갑자기 바뀌는 데서 옵니다.**

#### 고친 방법 — "이동/정지 번갈아"를 버리고 한 줄기 흐름으로

구조를 바꿨습니다.

| | 2차 | 3차 |
|---|---|---|
| 프레임 이동 | 카드마다 이동 트윈 + 정지 | **트윈 하나로 끝까지 일정 속도** |
| 카드 등장 | 정지 구간에 배치 | **흐름 위에 얹음** |
| 등장이 끝나는 지점 | 프레임이 멈춘 자리 | **프레임이 그 자리를 지나가는 시각** |

- `GALLERY_TRAVEL_SPEED` 880 → **520**. 520 / 380 = **1.37배로 pin 내내 일정**합니다.
- `ease`는 반드시 `"none"`입니다. 다른 이징을 주면 구간 안에서 속도가 변해 다시 끊깁니다.
- `galleryStops()` → **`galleryRestOffsets()`**. 이제 "멈추는 자리"가 아니라
  "다 뜬 순간 프레임이 지나고 있어야 할 자리"입니다. 두 가지를 겁니다.
  1. 앞 카드보다 최소 `GALLERY_MIN_GAP`(150px) 뒤 — 한 장씩 차례로 뜨게 합니다
     (시안에서 d의 중심이 c보다 59px 위라, 없으면 두 장이 동시에 뜹니다).
  2. **그 순간 카드의 위끝·아래끝이 모두 화면 안** — `[아래끝 − 화면높이, 위끝]`
     범위로 자릅니다. **이것이 위쪽 잘림을 막는 유일한 안전장치입니다.**
     프레임이 더 이상 멈추지 않으므로 "멈춰 있으니 안 잘린다"는 예전 논리는 못 씁니다.
- `GALLERY_LEAD`는 없앴습니다(겹칠 이동 구간 자체가 사라졌습니다).
- `SHOWCASE_TAIL_HOLD` 0.25 → **0.15**. 이 구간만 속도가 0이라 짧게 뒀습니다.
- `GALLERY_HOLD` → **`GALLERY_REVEAL`**로 이름을 바꿨습니다. 더 이상 아무것도
  붙잡지 않고 "떠오르는 길이"만 뜻합니다.

#### 고친 방법 — 등장을 pin 이전 구간으로 옮겼습니다

인트로 세 박자 중 **1박자(좌우 카드 등장)만 별도 트리거로 분리**해

  `end`가 pin 시작 지점과 같아서 카드가 다 앉는 순간 곧바로 pin으로 넘어갑니다.
- `addIntroBody()` — 문장(2박자)과 퇴장(3박자)만 pin 타임라인에 남습니다.
- **`travelStart`가 1.6 → `0`입니다.** 프레임이 pin의 첫 픽셀부터 흐릅니다.
  pin 시작 시점에 카드는 이미 제자리에 있으므로 기다릴 이유가 없습니다.
- `WORDS_START` 0.55 → **0**, `EXIT_START` 1.2 → **0.15**, `EXIT_DURATION` 1.15 → **1**.
- `INTRO_HANDOFF`는 없앴습니다(pin 안에 정지 구간이 없어 넘겨줄 것이 없습니다).
- **퇴장이 `to` → `fromTo`가 됐습니다.** 등장이 다른 트리거로 나갔기 때문에,
  `to`로 두면 시작값을 기록하는 시점에 따라(빠른 스크롤·refresh가 겹치면)
  등장 도중의 값이 시작값으로 굳을 수 있습니다.

### 브레이크포인트

프로젝트 표준인 **768 / 1280**을 씁니다. 공통 토큰의 `--layout_gutter`가 바뀌는

> **의도적으로 규칙을 하나 어겼습니다.** `AGENTS.md`는 "모바일부터 작성"이라고 하지만,

- **`svh`를 씁니다.** 모바일 주소창이 접힐 때 `vh`는 높이가 튀어 hero가 흔들립니다.
- **기울기를 완전히 버리지 않았습니다.** showcase 상단 두 장은 ±3.4 / 2.8도로 줄여
  남겼고(시안은 −15.55 / 13.07), archive 사진은
  `rotate(calc(var(--archive_photo_tilt) * 0.45))`로 시안 기울기에 비례시켰습니다.
  흩어진 인상은 남기되 격자를 깨지 않을 만큼입니다.
- **기울어진 사진은 `max-width: min(86%, 380px)`입니다.** 회전하면 가로로 커져서,
  그대로 두면 `.showcase`의 `overflow: hidden`에 가장자리가 잘립니다.
- **`!important`를 쓰지 않았습니다.** `.asworn_item_3 .asworn_figure` 같은 기존 규칙은
  `.asworn_list .asworn_figure`로 특정도를 맞추고, 블록이 파일 뒤에 있어 이기게 했습니다.

### 인터랙션

**데스크톱(1280px 이상)은 전혀 손대지 않았습니다.** 좌우 카드 등장(pin 이전 구간),
showcase pin + 일정 속도 흐름, 갤러리 등장, archive pin, as worn 띠 모두 그대로입니다.

**1279px 이하에 등장 연출을 새로 넣었습니다**(`initMobileReveal` / `buildMobileReveal`).
이 폭에서는 showcase가 흐름 배치라 붙잡아 둘 1920 캔버스가 없어 pin·scrub이 성립하지
않습니다. 인터랙션을 지우는 대신 같은 요소에 가벼운 "떠오르며 나타나기"를 겁니다.

- GSAP + ScrollTrigger를 씁니다(페이지가 이미 불러오고 있어 **추가한 라이브러리 없음**).
- `MOBILE_MOTION = "(max-width: 1279px) and (prefers-reduced-motion: no-preference)"` —
  CSS 경계(1279 / 1280)와 정확히 맞물립니다.
- `y: 42 → 0`, `opacity: 0 → 1`, `power2.out`, 0.75초, `start: "top 88%"`, **`once: true`**.
- **pin도 scrub도 쓰지 않습니다.** 좁은 화면에서 스크롤을 붙잡으면 터치 스크롤과 싸웁니다.
- **figure가 아니라 안쪽 img를 움직입니다.** figure에는 CSS가 기울기를 물려 두었는데
  GSAP이 figure에 인라인 transform을 쓰면 그 기울기가 사라집니다. (데스크톱과 같은 원칙)
- 문장 세 줄만 `stagger: 0.09`로 묶고, 사진은 각자 트리거를 답니다 —
  사진끼리 세로로 멀리 떨어져 있어 한 묶음으로 묶으면 화면 밖에서 다 끝납니다.

#### ★ resize에서 데스크톱 pin이 남던 문제 (실제로 겪음)

1920 → 414로 줄였더니 **가로 스크롤 1491px**, `is_pinned` 유지, pin-spacer 2개가
그대로 남았습니다. `createRebuilder`가 `resize`를 200ms 디바운스로만 받고 있었고,
그 사이 데스크톱 pin이 좁은 화면에 살아 있었기 때문입니다.

`createRebuilder`에 두 가지를 더했습니다.

1. **브레이크포인트 전용 리스너** — `matchMedia("(min-width: 1280px)")`의 `change`에서
   디바운스 없이 즉시 다시 만듭니다. 경계를 넘는 순간이 가장 위험한 지점입니다.
2. **`orientationchange`** — 세로 ↔ 가로 전환은 폭과 높이가 한꺼번에 바뀌는데
   `resize`가 따라오지 않는 기기가 있습니다. 같은 디바운스를 타므로 중복 실행되지 않습니다.

### 확인하지 못한 부분

- **이 세션의 미리보기 패널은 `visibilityState`가 `hidden`이라** 스크롤된 상태의 화면을
  다시 그리지 않습니다. 위 수치는 전부 `getBoundingClientRect` / `getComputedStyle`
  측정이고, **눈으로 보는 확인은 사용자가 해야 합니다.**
- **패널이 크기 변경 시 `resize` / `MediaQueryList change` 이벤트를 페이지에 전달하지
  않습니다.** 그래서 위 "resize 후 복귀"는 `window.dispatchEvent(new Event("resize"))`를
  직접 쏴서 확인했습니다(그때는 트리거 0개 / `is_pinned` 제거 / 가로 스크롤 0으로
  완전히 복귀했습니다). **브레이크포인트 전용 리스너는 이 환경에서 발화시킬 방법이 없어
  실제 동작을 보지 못했습니다** — 실제 브라우저에서 창을 드래그해 확인이 필요합니다.
- 실제 터치 스크롤 감각, 마우스 hover, 스크린리더 낭독.
- `.showcase_arc`는 이 폭에서도 화면보다 8px 넓습니다(`width: 102.0834%`).
  아치 곡선이 화면 폭에 정확히 맞도록 한 **의도된 값**이고 `.showcase`의
  `overflow: hidden`에 잘려 페이지 가로 스크롤은 생기지 않습니다.
- 히어로 영상 404는 이번 작업과 무관한 기존 문제입니다(HTML을 건드리지 않았습니다).

### 모바일 레이아웃 재설계 (2026-08-09, 2차)

사용자 확인: **"모바일 반응형 결과가 많이 깨진다."**
레퍼런스로 `https://obsidianassembly.com/`의 모바일 재배치 방식을 참고했습니다
(디자인 복제가 아니라 **어떻게 재배치·축소하는지**만 봤습니다).

#### 1차에서 무엇이 깨졌는가 — 원인 하나

사진에 `width: 100%` + `height: auto`를 줬습니다. 그러면 데스크톱이
`object-fit: cover`로 **잘라내던 구도가 풀려 원본 세로 비율이 그대로** 나옵니다.

| | 데스크톱(크롭) | 1차 모바일 |
|---|---|---|
| showcase_photo_a | 378 × 465 (비율 0.813) | 350 × **800** |
| showcase 섹션 | 3335px | **4148px** |
| 문서 전체(390px) | — | **9364px** |

사진 한 장이 화면을 통째로 채워 "스크롤 한 화면 = 사진 한 장"이 됐습니다.

#### 레퍼런스에서 읽은 수치 (390px에서 DOM 실측)

| 항목 | obsidianassembly | 1차 우리 |
|---|---|---|
| 본문 이미지 폭 | **화면의 28~66%**, 장마다 다름 | 90% 균일 |
| 이미지 높이 | 132~171px | ~800px |
| 좌우 여백 | 16px (일부 78px 들여쓰기) | 20px |
| 그리드 | 6열 / gap 16px | 1열 |
| 문서 높이 | 5711px | 9364px |

핵심은 **이미지를 화면 폭에 꽉 채우지 않고 크기를 서로 다르게 준다**는 것이었습니다.

#### 2차에서 세운 원칙

1. 사진은 화면을 채우지 않습니다. 폭을 **41~77%로 서로 다르게** 줍니다.
2. 크롭 구도는 `aspect-ratio`로 **데스크톱 프레임 비율 그대로** 지킵니다.
3. **좌우 정렬을 엇갈리게**(`align-self`) 해 시안의 "흩어져 떠 있는" 인상을
   세로 흐름에서 되살립니다.
4. 데스크톱을 축소해 넣지 않습니다. 구조 자체를 세로 흐름으로 다시 짭니다.

폭과 정렬은 figure가, 크롭 비율은 img가 맡습니다.

| 사진 | 모바일 폭 | 정렬 | 비율(시안 프레임 그대로) |
|---|---|---|---|

| b (기울임) | 58% | 오른쪽 | 366 / 458 |

시안의 상대적 크기 위계(c가 가장 크고 d가 가장 작음)가 그대로 유지됩니다.

#### ★ aspect-ratio를 figure가 아니라 img에 걸어야 합니다 (실제로 겪음)

처음에 `aspect-ratio`를 figure에 걸고 안쪽 img를 `height: 100%`로 뒀습니다.
부모 높이가 `auto`라 퍼센트 높이가 `auto`로 풀리고, **img의 원본 비율이 부모를
밀어 올려 aspect-ratio가 무시됩니다.** a가 217×267이어야 하는데 217×325로 나왔습니다.
img에 걸면 지정 비율이 원본 비율을 이기고 `cover`가 그 안에서 잘라 냅니다.

#### 태블릿 상한

퍼센트만 두면 태블릿에서 그대로 커집니다(753px에서 showcase가 **4448px**).
퍼센트는 좁은 화면의 리듬을 위한 값이고, 상한은 따로 잡았습니다 —
`.showcase_photo { max-width: 360px }`, `.showcase_photo_c { max-width: 480px }`.
753px에서 사진이 화면의 39~64%가 되어 레퍼런스 범위와 같아집니다.

#### archive는 2열을 유지합니다

1차에서 767 이하를 1열 + `max-width: 320px`로 했더니 사진 다섯 장이 각각 한 화면을
차지해 섹션이 **2458px**이 됐습니다. 2열(390px에서 168px씩)로 되돌리고,
**짝수 번째를 아래로 내려**(`nth-of-type(even)`에 `margin-top`) 격자가 딱딱해
보이지 않게 했습니다 — 데스크톱의 흩어진 배치를 좁은 화면에서 대신하는 장치입니다.
레퍼런스도 본문 이미지를 143px(37%)까지 씁니다.

**CSS**: `.asworn_body`를 `position: absolute; inset: 0`으로 사진 위에 덮고,

```

```

**JS**: `initAsworn`의 `render()`가 매 프레임 띠를 옮긴 뒤 `updateCentered()`를 부릅니다.
카드 중심이 트랙 한가운데에서 **카드 폭의 절반 안**에 들어온 한 장에만
`is_centered`를 붙입니다(카드 사이를 지나는 동안에는 둘 다 글을 유지).

지킨 것 세 가지입니다.

1. **`offsetLeft` / `clientWidth`를 매 프레임 읽지 않습니다.** 읽을 때마다 레이아웃을
   다시 계산시켜 8장이면 낭비입니다. `cacheItems()`가 배치가 바뀔 때
   (초기화 · `fillTrack` 후 · resize)만 재 둡니다.
2. **class는 바뀔 때만 씁니다.** 매 프레임 `classList.add`를 부르지 않습니다.
3. **데스크톱에서는 계산 자체를 건너뜁니다.** `matchMedia("(max-width: 1279px)")`가
   맞지 않으면 바로 빠져나오고 class도 지웁니다. 데스크톱은 글이 사진 옆에 따로
   있어 이 처리가 필요 없습니다.

### archive — 사진 다섯 장을 한 화면에 (2026-08-09, 5차)

요청: **"archive_frame의 사진 다섯 장이 한 페이지에 보였으면 좋겠다."**
레퍼런스로 `https://obsidianassembly.com/`의 **`-gc sticky`** 부분을 지정받았습니다.

#### 레퍼런스에서 읽은 구조 (390px에서 DOM 실측)

```
.-gc.sticky {
  position: sticky;  top: 0;
  height: 844px;                      /* 화면 정확히 한 장 */
  display: grid;
  grid-template-columns: repeat(6, 46.33px);   /* 6열 */
  column-gap: 16px;
}
부모 높이 5064px  →  sticky 높이의 6배가 스크롤 런웨이
```

핵심은 세 가지입니다.
1. **sticky 컨테이너가 정확히 화면 한 장 높이**입니다.
2. 그 안이 **6열 그리드**이고, 자식들이 `grid-column` / `grid-row`로 자리를 잡아
   한 화면을 채우는 구성이 됩니다.
3. **부모 섹션이 훨씬 높아** 그 차이만큼 화면에 머뭅니다.

#### 무엇이 문제였는가

1279px 이하 archive는 2열로 세로로 흘렀습니다. 390px에서 섹션이 1159px
(화면 1.4장)이라 사진 다섯 장을 한 번에 볼 수 없었습니다.

#### 고친 방법

레퍼런스와 같은 구조로 바꿨습니다.

```css
.archive        { height: 200svh; }        /* 런웨이 */
.archive_frame  { position: sticky; top: 0; height: 100svh;
                  display: grid;
                  grid-template-columns: repeat(6, minmax(0, 1fr));
                  grid-template-rows: auto repeat(4, minmax(0, 1fr)); }
```

첫 줄은 글(제목 · 연도 · 링크)이 `grid-column: 1 / -1`로 쓰고,
나머지 네 줄을 사진 다섯 장이 서로 다른 크기로 나눠 씁니다.

| 사진 | 열 | 행 | 390px 실제 크기 |
|---|---|---|---|
| 1 | 1 / 4 | 2 / 4 | 177 × 275 |
| 2 | 4 / 7 | 2 / 3 | 174 × 138 |
| 3 | 4 / 7 | 3 / 4 | 171 × 134 |
| 4 | 1 / 3 | 4 / 6 | 114 × 273 |
| 5 | 3 / 7 | 4 / 6 | 242 × 282 |

데스크톱의 흩어진 배치를 좁은 화면에서 대신하는 구성입니다.

지킨 것:

- **`.archive`의 `overflow: clip`이 그대로 필요합니다.** `hidden`으로 바꾸면
  스크롤 컨테이너가 생겨 안쪽 sticky가 죽습니다(이 파일 위쪽 주석과 같은 이유).
- **칸 높이가 정해져 있어 사진은 `object-fit: cover`로 채웁니다.**
  데스크톱은 원본 비율(`height: auto`)이지만, 한 화면에 다 담으려면
  칸에 맞추는 쪽이 맞습니다.
- 기울기는 시안값의 0.45 → **0.35배**로 더 줄였습니다. 칸이 좁아져
  0.45로는 옆 칸을 침범합니다.
- 그 해에 사진이 네 장뿐이면(col_chaikim 2021) 4번이 남는 칸을 넘겨받아
  빈 구멍이 생기지 않게 했습니다(`.archive_photo_5.is_empty ~ .archive_photo_4`).

#### ★ sticky라 등장이 한꺼번에 떠 버립니다

프레임이 화면에 붙어 있으면 다섯 장의 트리거 지점이 거의 같아집니다.
그대로 두면 `start: "top 88%"`가 동시에 걸려 다섯 장이 한 번에 뜹니다.

그래서 archive만 **섹션의 스크롤 런웨이에 `scrub`으로 묶었습니다** —
`trigger: .archive`, `start: "top top"`, `end: "bottom bottom-=20%"`.
데스크톱의 pin + scrub과 같은 생각이고, sticky가 떨어지기 전에 다섯 장이
다 떠 있도록 끝을 20% 앞당겼습니다.
값은 `MOBILE_ARCHIVE_DURATION`(0.55) / `MOBILE_ARCHIVE_STAGGER`(0.6)이며,
scrub이라 초가 아니라 스크롤 진행도입니다. STAGGER가 DURATION보다 커야
한 장씩 또렷하게 끊어져 뜹니다.

|---|---|---|---|---|
| 375 × 812 | **sticky** 375 × 812 | **예** | 0 | 2.00배 |
| 390 × 844 | **sticky** 390 × 844 | **예** | 0 | 2.00배 |

- 프레임 높이가 세 폭 모두 화면 높이와 **오차 2px 이내**, `top: 0`에 붙습니다.
- 사진 크기가 폭에 따라 함께 커집니다(375에서 115~223px, 753에서 225~446px).
- **데스크톱 무회귀**: archive 920px, 프레임 `position: relative`(sticky 아님),

  265×333 / 332×388), `object-fit: fill`(원본 비율 유지).
  showcase pin 931, 문서 높이 7863, 가로 스크롤 0, 실패한 요청 0건.
- 문서 높이(390px) 4982 → 5511(런웨이가 더해진 만큼), archive 1159 → **1688**
  이지만 **보이는 것은 한 화면**입니다.

#### 확인하지 못한 부분

- **캡처가 또 사진 타일을 빠뜨렸습니다.** 글 블록만 찍히고 사진 자리가 비어
  나왔는데, `elementFromPoint`로 확인하니 다섯 장 모두 제자리에 그려져 있었습니다
  (hit-test가 자기 자신 반환, opacity 1, 이미지 로드 완료).
  **패널의 합성 문제**이고 레이아웃 문제가 아닙니다.
  위 수치는 전부 좌표 측정이므로 **눈 확인은 사용자가 해야 합니다.**
- sticky가 붙었다 떨어지는 감각, 다섯 장이 하나씩 뜨는 속도.

### archive — 세로 카드 덱으로 (2026-08-09, 6차)

요청: **"연도별 탭이 위쪽에 있고 세로로 카드 이미지가 보이게. 다섯 장을 터치해서
올리면 넘어가고, 위 연도를 누르면 이미지가 바뀌는 구조."**
레퍼런스로 `obsidianassembly.com`의 오브젝트 시퀀스 화면을 지정받았습니다.

#### 레퍼런스에서 읽은 구조 (DOM 실측)

카드들이 **같은 자리에 겹쳐 있고**, 앞뒤는 오직 `transform`과 상태 class로 만듭니다.

```
.object-wrapper        grid-column: 2/6;  grid-row: 1/3   ← 다섯 장 모두 같은 칸
  transform: matrix(0.5, 0, 0, 0.5, tx, 0)                ← 축소 + 이동으로만 자리를 냄
.-active .object-wrapper / .-under .object-wrapper        ← 상태 class
```

#### 바뀐 것

5차의 6열 그리드(다섯 장을 흩어 놓기)를 **세로 덱**으로 바꿨습니다.

| | 5차 | 6차 |
|---|---|---|
| 배치 | 6열 × 4행에 흩뿌림 | **같은 자리에 겹친 덱** |
| 섹션 | 200svh + sticky 프레임 | **100svh, sticky 없음** |
| 넘기기 | 없음(스크롤로 등장만) | **위로 밀기(pointer)** |
| 위치 표시 | 없음 | **카운터 1 / 5** |

HTML에 `.archive_deck` 래퍼와 카운터를 더했습니다.
**데스크톱에서는 이 래퍼가 `position: static`이라** containing block이 되지 않고,
안쪽 figure들이 예전처럼 `.archive_frame` 기준 시안 좌표에 그대로 놓입니다.

덱 배치는 CSS 커스텀 속성으로 합니다(js가 값을 씁니다).

```
transform: translate(-50%, var(--archive_deck_y))
           scale(var(--archive_deck_scale))
           rotate(calc(var(--archive_photo_tilt) * 0.3));
```

뒤로 한 장 갈 때마다 `DECK_STEP_Y`(46px) 위로, `DECK_STEP_SCALE`(0.075) 작게,
`DECK_STEP_FADE`(0.24) 흐려집니다. `DECK_VISIBLE_DEPTH`(3)보다 뒤는 맨 뒤와 같은
자리에 숨습니다. 390px 실측: 273×423 / 251×391 / 236×362 / 218×332 / 209×327,
불투명도 1 / 0.76 / 0.52 / 0.28 / 0.28.

#### ★ 두 번 걸린 함정

**1. `top: auto`를 빠뜨리면 카드가 세로로 늘어납니다.**
기본 규칙의 `top: var(--archive_photo_top)`이 남은 채 `bottom: 0`을 주면
위아래가 함께 고정돼 높이가 내용이 아니라 그 간격으로 정해집니다.
266×355여야 할 카드가 **266×542**가 됐습니다.

**2. 카드 높이는 `aspect-ratio`가 아니라 덱에 대한 퍼센트여야 합니다.**
고정 비율로 두면 글 블록 높이가 화면마다 달라질 때 카드가 덱 밖으로 나갑니다.
`height: 72%`로 두면 덱이 어떤 높이든 항상 안에 들어오고, 위로 밀려 올라가는
뒤 카드 자리도 남습니다. 이미지는 `object-fit: cover`로 상자를 채웁니다.

#### 밀어 넘기기

`initArchiveDeck()` — **GSAP을 쓰지 않습니다.** 상태가 "몇 번째 장인가" 하나뿐이고
자리 이동은 커스텀 속성 + CSS transition으로 충분하며 스크롤과도 무관합니다.
그래서 모션 감소 설정이나 GSAP 로드 실패와 관계없이 항상 넘어갑니다.

Pointer 이벤트라 마우스와 손가락이 같은 코드로 들어옵니다.
`DECK_SWIPE_THRESHOLD`(56px)보다 많이 위로 밀면 다음 장, 아래로 밀면 이전 장입니다.

> **`.archive_deck { touch-action: none }`이 반드시 필요합니다.** 없으면 세로
> 드래그를 브라우저가 페이지 스크롤로 가져가 pointermove가 오지 않습니다.
> 대신 그 영역에서는 페이지가 스크롤되지 않으므로 **카드 폭을 72%로 제한**해
> 좌우 여백(375px에서 56px씩)을 스크롤할 수 있는 자리로 남겼습니다.

연도를 바꾸면 사진 세트가 통째로 갈리므로 첫 장으로 돌아갑니다.
`initArchive`가 사진을 다 갈아 끼운 뒤 `archive_year_change` 커스텀 이벤트를
보내고 덱이 받습니다(두 경로 모두에서 보냅니다).

#### 검증

**덱 조작 (두 페이지, 375 / 390)**

- 위로 밀기 ×5 → `1 → 2 → 3 → 4 → 5 → 1`(**되감김**), 아래로 밀기도 역순 정상.
- 임계값 미만(20px)은 **바뀌지 않음**.
- 연도 2020 클릭 → 맨 앞 장이 `archive_2020_1.png`로 갈리고 **카운터가 1로 리셋**.
- 다섯 장 모두 **덱 안에 들어옴**(`allInsideDeck: true`), 이미지 전부 로드,
  `elementFromPoint`가 각 카드 중심에서 그 이미지를 반환(실제로 그려져 있음).

**데스크톱 무회귀 (1920)**

`.archive_deck`이 `position: static`, 카운터 `display: none`,

(320×389 / 424×553 / 368×450 / 265×333 / 332×388), 한 화면 안,

#### 확인하지 못한 부분

- **이 패널은 스타일 재계산이 한 박자 늦습니다.** `getComputedStyle`이 강제로 넣은
  인라인 transform조차 이전 값을 돌려줬습니다. 그래서 위 수치는 커스텀 속성을
  흔들었다 되돌려 계산을 두 번 강제한 뒤 잰 값입니다.
- **캡처는 또 카드 타일을 빠뜨렸습니다.** 연도 탭까지만 찍히고 덱 자리가 비었는데,
  같은 시점에 다섯 장 모두 `naturalWidth > 0`이고 hit-test가 자기 이미지를
  반환했습니다. **패널의 합성 문제**입니다.
  **눈으로 보는 확인은 사용자가 해야 합니다.**
- 실제 손가락으로 미는 감각, `DECK_SWIPE_THRESHOLD`(56px)가 적당한지.
- 덱 위에서는 페이지가 세로로 스크롤되지 않습니다(의도). 좌우 여백이나
  연도 탭 영역을 잡고 스크롤해야 합니다 — 실제 기기에서 답답하지 않은지 확인 필요.

#### 실제 기기 확인 후 보정 (2026-08-09, 6차-2)

사용자가 실제 기기 화면을 보내 세 가지를 지적했습니다.
**① 카드가 쌓이면 안 보인다 ② 카드가 너무 길어 아래가 잘린다
③ Reverse Now / Shop Now 버튼을 사진 한가운데로.**

**① 잘림의 진짜 원인은 sticky를 뺀 것이었습니다.**
6차에서 섹션을 100svh로 두고 sticky를 없앴더니, 섹션이 스크롤과 함께 흘러
화면에 걸쳐 있는 동안 카드 아래가 잘렸습니다. 5차의 sticky를 되살렸습니다 —
`.archive { height: 170svh }` + `.archive_frame { position: sticky; top: 0; height: 100svh }`.
런웨이는 70svh만 둡니다(덱이 세로 드래그를 가져가므로 길면 지나가기 답답합니다).

**② 카드 길이는 퍼센트가 아니라 화면 기준(svh)으로 잡았습니다.**

```
--archive_card_h: min(42svh, 400px);
--archive_pad_bottom: clamp(28px, 5vw, 56px);
```

6차의 `height: 72%`(덱 대비)는 글 블록 높이에 따라 길이가 들쭉날쭉했습니다.
390px에서 카드가 274×361 → **266×354**로 짧아졌습니다.

**③ ★ 카드를 덱이 아니라 프레임 바닥 기준으로 앉혔습니다.**
`.archive_deck`을 `position: relative` → **`static`**으로 바꿨습니다.
relative면 카드가 덱 높이(글 블록에 따라 정해지는 flex 잔여값)를 기준으로 앉는데,
그 값이 화면과 어긋나 **프레임 바닥을 42px 넘겼습니다**.
static이면 카드가 `.archive_frame`(유일한 위치 기준)의 바닥에서
`--archive_pad_bottom`만큼 띄워 앉아 계산 의존이 사라집니다.
`flex: 1`이라 덱 상자 자체는 남는 자리를 그대로 차지하므로 드래그 영역은 그대로입니다.

그 덕에 링크를 카드 한가운데에 놓는 계산이 가능해졌습니다.

```
.archive_more {
  position: absolute;  left: 50%;
  bottom: calc(var(--archive_pad_bottom) + var(--archive_card_h) / 2);
  transform: translate(-50%, 50%);
}
```

사진 위에 올라가므로 어두운 알약 판 + 흰 글씨로 바꾸고 화살표도 흰색으로 뒤집었습니다.

**④ 쌓인 카드가 보이도록** 세 가지를 함께 고쳤습니다.
`DECK_STEP_Y` 46 → **56**(더 많이 드러남), `DECK_STEP_FADE` 0.24 → **0.15**
(세 장 뒤도 0.55 남음), 그리고 카드가 짧아져 같은 56px이라도 드러나는 비율이 커집니다.
카드마다 `box-shadow`를 넣어 겹친 가장자리가 구분됩니다.

카운터도 `right/bottom: 0` → 프레임 여백 기준으로 옮기고 옅은 판을 깔았습니다.

"사진 가운데"는 사진과 가로 중심을 맞추라는 뜻이었습니다.

레퍼런스와 다시 맞춘 세 가지입니다.

| | 6차-2 | 6차-3 |
|---|---|---|
| 링크 위치 | 사진 한가운데에 겹침 | **카드 아래에 따로** |
| 링크 모양 | 어두운 알약 + 흰 글씨 | **테두리만 있는 빈 알약**(EXPLORE OBJECTS와 같은 꼴) |
| 뒤 카드 | 반투명(0.85 / 0.7 / 0.55) | **전부 불투명** |
| 카드 기울기 | `rotate(tilt × 0.3)` | **없음** |
| 보이는 장 수 | 앞 + 뒤 3장 | **앞 + 뒤 2장** |
| 카운터 | 우하단 알약 | **오른쪽 원, 카드 세로 가운데** |

**뒤 카드를 불투명하게 한 이유**: 반투명하면 앞뒤 사진이 서로 비쳐 지저분해집니다
(사용자가 보낸 화면에서 실제로 그렇게 보였습니다). 레퍼런스의 뒤 카드도 흐려지지
않습니다. 깊이는 **크기 차이와 그림자로만** 만듭니다.

**기울기를 없앤 이유**: 레퍼런스의 카드 더미는 반듯하게 겹쳐 있습니다.
기울이면 겹친 가장자리가 어긋나 지저분해 보입니다.

버튼 자리는 `--archive_action_h`(90px)로 잡아 두고 카드가 그 위에서 끝납니다
(`bottom: calc(--archive_pad_bottom + --archive_action_h)`). 그래서 둘이 절대 겹치지 않습니다.

조절값: `DECK_STEP_Y` 56 → **48**, `DECK_STEP_SCALE` 0.07 → **0.06**,
`DECK_STEP_FADE` 0.15 → **0**, `DECK_VISIBLE_DEPTH` 3 → **2**,
`--archive_card_h` 400 → **380px 상한**.

#### 검증 (390 × 844)

- 프레임이 화면에 정확히 맞춰 섬(0~844), **다섯 장 전부 화면 안**.
- 카드 266×354 / 250×333 / 234×312, **불투명도 전부 1**,
  transform이 `matrix(0.94, 0, 0, 0.94, -133, -48)` — **회전 성분 없음**(순수 축소 + 이동).
- 뒤 카드 **37px씩 드러남**.
- **버튼이 카드와 겹치지 않음**(`overlapsCard: false`), 카드 아래 **20px** 간격,
  289×52, 가로 중앙, 화면 안.
- 카운터 54×54 원이 카드 오른쪽 **세로 한가운데**(오차 6px 이내), 화면 안, 내용 `1 / 5`.
- 다섯 장 모두 이미지 로드 + `elementFromPoint`가 각 카드에서 IMG 반환,
  카운터도 hit-test 통과.
- 가로 스크롤 0.

**데스크톱 무회귀**: 프레임 `relative`, 덱 `static`, 카운터 `display: none`,
Shop Now 링크 `position: static`으로 왼쪽 글 컬럼에 그대로, 사진 시안 크기 유지,
archive 920 / pin 1152, showcase pin 931, 문서 7863.

#### 확인하지 못한 부분

- **캡처가 카드와 카운터 타일을 또 빠뜨렸습니다.** 버튼(테두리 알약)과 연도 탭은
  찍혔는데 카드 자리가 비었습니다. 같은 시점에 다섯 장 모두 이미지가 로드돼 있고
  `elementFromPoint`가 각 카드에서 IMG를 반환했습니다 —
  **패널의 합성 문제**입니다. 눈 확인은 사용자가 해야 합니다.
- 카드 더미의 겹침 간격(37px)과 크기 차이가 레퍼런스와 비슷한 인상인지.

#### 첫 카드 고정 / 간격 불균일 수정 (2026-08-09, 6차-4)

사용자 지적: **"첫번째 카드가 계속 위에 있어. 모든 화면 크기에서 연도탭과 사진
간격이 동일하게. 어떤 건 너무 멀어."**

##### ★ 두 문제의 원인이 하나였습니다 — 덱에 남은 GSAP transform

`buildMobileReveal`이 `.archive_deck`을 `y`로 띄우고 있었습니다.
그러면 GSAP이 덱에 인라인 `transform`을 남기는데,
**transform이 걸린 요소는 그 안의 절대배치 자식에게 기준 상자(containing block)가 됩니다.**

그때까지 카드는 `.archive_frame` 바닥 기준으로 앉도록 짜여 있었는데,
실제 기기에서는 트윈이 실행되므로 기준이 프레임 → 덱으로 바뀌어
카드 자리가 통째로 틀어졌습니다.
**이 세션의 미리보기 탭은 rAF가 돌지 않아 트윈이 실행되지 않았고,
그래서 지금까지 이 문제가 측정에 잡히지 않았습니다.**

고친 것:

1. **덱 등장을 `opacity`만으로** 바꿨습니다(`y` 제거). transform을 남기지 않습니다.
2. **카드를 덱의 "위쪽" 기준으로** 앉혔습니다.
   `top: var(--archive_deck_head)` — 덱은 연도 탭 바로 아래에서 시작하는 flex
   항목이라, 위에서부터 재면 **연도 탭과 카드 사이 간격이 화면 크기와 무관하게
   일정**합니다. (바닥 기준이면 화면이 높을수록 벌어집니다 — 지적하신 그 현상입니다.)
3. 덱을 다시 `position: relative`로 되돌렸습니다(2번의 기준이 되어야 하므로).
   아래쪽 넘침은 아래 `--archive_card_real`이 막습니다.

##### 화면이 낮을 때의 안전장치

```css
--archive_card_real: min(
  var(--archive_card_h),
  calc(100% - var(--archive_deck_head) - var(--archive_action_h))
);
```

카드 높이와 카운터 위치가 **같은 값**을 씁니다. 화면이 낮으면 카드가 줄어드는데,
따로 계산하면 카운터가 카드 밖으로 벗어납니다(실제로 667px 화면에서 그랬습니다).
퍼센트는 둘 다 덱 높이를 기준으로 풀리므로 값이 항상 일치합니다.

`--archive_deck_head`(104px)는 뒤 카드가 위로 겹쳐 올라갈 자리입니다.
js의 `DECK_VISIBLE_DEPTH × DECK_STEP_Y`(2 × 48 = 96)보다 커야
맨 뒤 카드가 덱 위로 삐져나가지 않습니다.

##### "첫 카드가 계속 위에" 에 대해

z-index 자체는 정상이었습니다 — 밀 때마다
`photo_1 → photo_2 → photo_3`으로 맨 앞이 바뀌는 것을 hit-test로 확인했습니다
(`--archive_deck_z` 5,4,3,2,1 → 1,5,4,3,2 → 2,1,5,4,3).
실제 기기에서 그렇게 보인 것은 위 transform 문제로 카드 자리가 틀어져
겹침이 어긋나 있었기 때문으로 봅니다.

#### 검증

| 화면 | 연도탭 ~ 맨 앞 카드 | 카드 | 덱 transform | 다 보임 | 버튼 겹침 | 카운터 중앙 |
|---|---|---|---|---|---|---|
| 390 × 844 | **120px** | 266 × 354 | `none` | 예 | 없음 | 맞음 |
| 375 × 667 | **120px** | 255 × 222 | `none` | 예 | 없음 | 맞음 |

- **간격이 두 화면에서 정확히 같습니다**(120px). 낮은 화면에서는 카드만 줄어듭니다.
- 밀기 `1 → 2 → 3 → 4 → 5 → 1` 되감김 정상, 맨 앞 카드가 매번 바뀜
  (`1:archive_photo_1 → 2:archive_photo_2 → 3:archive_photo_3`).
- 가로 스크롤 0.

**데스크톱 무회귀 (1920)**: 덱 `static`, 카운터 `display: none`,
Shop Now 링크 `position: static` 103px(왼쪽 글 컬럼 그대로),
사진 시안 크기 유지(320×389 / 424×553 / 368×450 / 265×333 / 332×388),
한 화면 안, archive 920 / pin 1152, showcase pin 931, 문서 7863, 실패한 요청 0건.

#### 앞으로 주의할 것

- **`.archive_deck`에 transform을 걸지 마세요.** GSAP으로 띄울 때도 `opacity`만
  씁니다. transform이 생기는 순간 카드의 기준 상자가 바뀌어 배치가 무너집니다.
- 연도 탭과 카드 간격을 바꾸려면 `--archive_deck_head`(104px)를 조절하세요.
  단, `DECK_VISIBLE_DEPTH × DECK_STEP_Y`보다 커야 합니다.

#### 데스크톱 캐러셀 되돌림 — 캐러셀은 1279px 이하 전용 (2026-08-09, 7차)

사용자 지적: **"넘기는 건 모바일만 해달라고 했는데 데스크탑에도 들어가 있다.
데스크탑은 이전과 동일하게 되돌리고 모바일만 `<>` 버튼."**

**제 잘못입니다.** 캐러셀 작업 전에 범위를 여쭀을 때 "둘 다"라는 답을 받았는데,
그 질문은 **어느 페이지**(col_chaikim / col_chaikimyoungjin)를 물은 것이었지
데스크톱까지 포함하는 뜻이 아니었습니다. 그런데 데스크톱 레이아웃까지 캐러셀로
바꿔 버렸습니다.

`docs/design-analysis.md`의 반응형 기준도 다시 확인했습니다.

```
- 1280px: 헤더 메뉴 상시 노출, hero 높이 986px 고정, 시안 좌표 그대로 적용
```

**1280px 이상은 "시안 좌표 그대로"**입니다. 캐러셀은 이 기준에 맞지 않았습니다.

#### 되돌린 방법

데스크톱 부분을 **커밋 `beb08d1`(캐러셀 직전 상태)에서 그대로 복원**했습니다.
손으로 다시 쓰지 않고 그 시점의 파일에서 데스크톱 base 구간을 떼어 왔습니다.

| | 캐러셀 적용 중 | 지금 |
|---|---|---|
| `.showcase` / `_frame` | 100vh / 100% | **3335px** (시안) |
| 아치 · 그라디언트 | 40% 비율 | **738px / 2597px** (시안) |
| 사진 c~g | 가운데 캐러셀 슬라이드 | **시안 좌표 절대배치** |
| 문장 | 화면 한가운데 | **시안 계단 배치**(top 0/117/229, left 0/266/0) |
| 프레임 이동 | 없음 | **2255px를 1.37배로 흐름** |
| 갤러리 등장 | 없음 | **스크롤에 맞춰 한 장씩** |

> **문장 가운데 정렬도 함께 되돌아갔습니다.** "데스크탑은 이전과 동일하게"라는
> 말을 그대로 따랐기 때문입니다. 데스크톱에서도 문장을 가운데로 두고 싶으시면
> 말씀해 주세요 — 그 부분만 다시 넣을 수 있습니다. 모바일은 가운데 정렬 그대로입니다.

#### 캐러셀을 좁은 화면 전용으로 가두는 방법

HTML의 캐러셀 래퍼는 그대로 둡니다(마크업을 두 벌 만들지 않기 위해서입니다).

- **CSS**: 캐러셀 규칙 전체를 `@media (max-width: 1279px)` 안으로 옮겼습니다.
  데스크톱에서는 `.showcase_carousel` / `_viewport`가 **위치 지정이 없는 평범한
  div**라 안쪽 figure의 `absolute`가 `.showcase_frame` 기준으로 그대로 풀립니다.
  즉 시안 좌표가 아무 방해 없이 살아납니다. 버튼만 `display: none`으로 감춥니다.
- **JS**: `initShowcaseCarousel`에 `matchMedia("(max-width: 1279px)")` 게이트를
  더했습니다. **조건이 어긋나면 `is_current`와 `aria-hidden`을 걷어 냅니다** —
  남겨 두면 데스크톱에서 보이는 사진 네 장을 읽기 도구가 건너뜁니다.
  경계를 넘나들 때도 `change` 이벤트로 다시 맞춥니다.

#### 검증

**데스크톱 1920 × 1080 (두 페이지)**

- 프레임 3335px, `.showcase` pin 시 1080, pin 길이 enter 1080 / showcase 1705 /
  archive 1152, 문서 높이 8637 — **캐러셀 이전 수치와 완전히 동일**.

#### 앞으로 주의할 것

- **데스크톱(1280px 이상)은 시안 좌표가 기준입니다.** 새 인터랙션을 넣을 때
  이 좌표를 흔드는 방식이면 좁은 화면 전용으로 가두세요.
- 캐러셀처럼 **같은 마크업을 폭에 따라 다르게 쓰는 경우**, CSS만 나누면

  다른 폭에서 접근성이 깨지지 않습니다.
