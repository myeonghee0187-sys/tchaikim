# bespoke 페이지 작업 기록

`pages/bespoke/` 폴더의 작업 내역입니다. 저장소 전체 기록은 `docs/PROJECT_CONTEXT.md`에
있고, 이 문서는 이 폴더 안에서만 끝나는 작업을 남깁니다.

이 폴더에는 **페이지 세 개**가 들어 있습니다.

| 파일 | 화면 | CSS |
|---|---|---|
| `index.html` | Bespoke 메인 | `css/bespoke.css` (+ `bespoke_base.css`) |
| `reservation.html` | 예약 폼 | `css/reservation.css` (+ `bespoke_base.css`) |
| `reservation_done.html` | 예약 완료 | `css/reservation_done.css` (+ `bespoke_base.css`) |

**`css/bespoke.css`와 `js/bespoke.js`는 `index.html`만 불러옵니다.** 이 두 파일을
고쳐도 예약 페이지 두 개에는 영향이 없습니다. 반대로 `css/bespoke_base.css`는
세 페이지가 함께 쓰므로 고칠 때 세 페이지를 모두 확인해야 합니다.

## Materials 섹션 — 원단 선택 인터랙션 (2026-08-09)

정지 화면이던 원단 섹션을, **스와치나 이름에 마우스를 올리면 큰 사진과 설명이
그 원단으로 바뀌는** 방식으로 바꿨습니다.

- `index.html` — materials 섹션 마크업 교체
- `css/bespoke.css` — materials 블록에 상태 규칙 추가
- `js/bespoke.js` — `initMaterialsSelector()` 추가

### 레퍼런스 — eternalblue.co.nz `.ingredient-slider__grid`

구조를 실측했더니 **이 섹션과 배치가 거의 같았습니다.**

| 레퍼런스 | 여기 (이미 있던 것) |
|---|---|
| `.ingredient-slider__image` (큰 사진, 페이드) | `.materials_texture` |
| `.ingredient-slider__static-content` (머리글) | **없음 → 새로 추가** |
| `.ingredient-slider__slider-tabs` (썸네일 6칸) | `.materials_swatches` |
| `ul.ingredient-slider__number-tab` (이름 목록) | `.materials_list` |
| `.ingredient-slider__tab-description` | `.materials_caption` |

그래서 레이아웃을 새로 짜지 않고 **상태 규칙만 얹었습니다.**
레퍼런스에서 그대로 가져온 값:

| 대상 | 값 |
|---|---|
| 썸네일 | `opacity: .5` → `.active { 1 }`, `transition: .4s ease-in-out` |
| 이름 행 | `opacity: .5` → `.active { 1 }`, `transition: .3s ease` |
| 큰 사진 | `transition: opacity .4s ease`, `.is-fading { opacity: 0 }` |
| 번호 칸 | `min-width: 24px`, 이름과의 `gap: 16px` |
| 화살표 | 활성 행에만 표시 |

### ★ 큰 사진은 크로스페이드가 아닙니다

레퍼런스는 사진 두 장을 겹쳐 바꾸지 않습니다. **한 장을 0.4초에 걸쳐 흐리게 만든
뒤 `src`를 갈아 끼우고 다시 나타냅니다.** 중간에 배경이 비칩니다. 그대로 옮겼습니다
(process 섹션의 크로스페이드와 의도적으로 다릅니다).

전환 시간은 JS가 `getComputedStyle(...).transitionDuration`으로 **CSS에서
읽습니다.** 모션 감소 설정이면 `--materials_fade`가 `--duration_base`(0.01ms)라
기다리지 않고 즉시 바뀝니다 — 숫자를 JS에 박아두지 않은 이유입니다.

빠르게 훑고 지나갈 때를 위해 토큰으로 경합을 막습니다. 흐려지는 동안 더 최근
요청이 오면 앞선 차례는 버리고, 마지막 원단으로 마무리합니다(실측 확인).

### 시안과 다르게 판단한 것

- **이름 행만 불투명도 대신 기존 색 전환을 유지했습니다.** 시안이 이미
  `--color_text_muted` → `--color_text`를 쓰고 있어서, 폰트 색을 그대로 두라는
  요구에 맞췄습니다. 전환 시간만 레퍼런스(.3s)를 따릅니다.
- **머리글 문단(`.materials_intro`)은 새로 넣은 내용입니다.** 레퍼런스의
  `static-content` 자리입니다. 빼려면 `index.html`의 그 한 줄만 지우면 됩니다
  (다른 곳에서 참조하지 않습니다). 섹션 높이 1408 → **1485**의 원인입니다.
- **설명 6개를 새로 썼습니다.** 기존 것은 Silk 하나뿐이었습니다(Figma 카피).
  형식은 그대로 유지했습니다 — 형용사 세 개 + 설명. 1920에서 여섯 개 모두
  정확히 **140px(5줄)**로 맞춰 두었습니다.
- **`<div>` 대신 `<button>`을 씁니다.** 레퍼런스는 `cursor: pointer`만 걸어
  키보드로 고를 수 없습니다. `reset.css`가 button의 색·글꼴·여백을 상속으로
  되돌려 두어서 글자 크기와 색은 이전 마크업과 똑같이 나옵니다(측정 확인).

### 반드시 지켜야 하는 것

1. **`.materials_texture`에 `align-self: flex-start`가 필요합니다.** 없으면 flex
   기본값 stretch가 이 상자를 오른쪽 열 높이에 맞춰 늘여서 `aspect-ratio: 466/678`
   (시안값)을 무시합니다. 머리글이 들어오면서 실제로 466×**755**가 됐습니다.
2. **`.materials_detail`은 `flex-wrap: wrap` + 캡션 `flex: 1 1 360px`입니다.**
   1280px 화면에서 오른쪽 열이 606px뿐이라 목록(375) + gap(100)을 빼면 설명이
   **131px**까지 눌렸습니다(실측). 45단어짜리 설명이 그 폭에서는 읽히지 않습니다.
   레퍼런스도 좁은 폭에서는 세로로 쌓습니다(`grid-template-columns: 1fr`).
   고정 브레이크포인트 대신 flex-basis로 두어 어느 폭에서든 알아서 내려갑니다.
3. **캡션 높이를 JS가 미리 잡습니다.** 안 그러면 원단을 옮길 때마다 줄 수가 달라져
   섹션이 들썩입니다. 웹폰트 적용 후와 폭이 바뀔 때 다시 잽니다
   (shop_detail 아코디언과 같은 방식).
4. **큰 사진의 대체 텍스트는 스와치의 것을 고쳐 씁니다**(`" swatch"` →
   `" shown close up"`). 이름 목록에서 만들면 `"Seasonal Fabric fabric ..."`처럼
   겹칩니다 — 실제로 그렇게 났다가 고쳤습니다.
5. **hover는 버블링하지 않으므로 `mouseover`로 위임합니다.** 버튼 안쪽 요소를
   지날 때마다 다시 들어오지만 같은 값이면 바로 빠집니다.

### ★ 원단 사진이 원본보다 크게 그려집니다 (이번 작업과 무관한 기존 문제)

여섯 장 모두 **180 × 200**인데 큰 사진 자리는 **466 × 678**입니다. 가로 2.6배,
세로 3.4배로 늘어납니다. **바꾸기 전에도 `silk.png`가 같은 자리에 같은 크기로
들어가 있었으므로 화질은 이전과 동일합니다.** 여섯 장의 크기가 모두 같아서
어느 원단을 골라도 차이가 없습니다. 선명하게 하려면 원단 사진을 다시
내보내야 합니다.

### 확인하지 못한 부분

- **화면 캡처를 하지 못했습니다**(이 세션의 미리보기 패널이 이 구간을
  합성하지 못합니다). 위 수치는 전부 `getBoundingClientRect` /
  `getComputedStyle` 측정입니다. **실제 마우스로 훑을 때의 페이드 감각과
  0.4초가 적당한지는 사용자가 봐야 합니다.**
- 미리보기 탭이 `document.hidden`이라 **class가 바뀐 뒤의 다시 칠하기(불투명도
  0.5 → 1, 화살표 등장)를 눈으로 보지 못했습니다.** DOM 상태로만 확인했습니다.
- **`document.hasFocus()`가 false라 `.focus()`가 `focusin`을 쏘지 않습니다.**
  키보드 경로는 `focusin`을 직접 디스패치해 핸들러가 올바로 도는 것만
  확인했습니다(`001000` + 해당 설명).
- `prefers-reduced-motion: reduce` 실제 동작. 이 환경에서 에뮬레이트할 수
  없었습니다.

## Process 섹션 — 큰 사진 한 장 + 번호 목록 (2026-08-10, 최종)

**같은 날 세 번 고쳤습니다.**
① thecube.dk 참고 pin 스크롤 → ② felix-nieto 참고 hover 아코디언 →
③ **j-cat 참고 "큰 사진 무대 + 번호 목록"**(현재). ②의 색 차오름 연출은
그대로 가져왔고, 사진과 글의 주종 관계만 뒤집었습니다.

- `index.html` — process 섹션 마크업 교체
- `css/bespoke.css` — process 블록 전체 교체
- `js/bespoke.js` — `initProcessSteps()` 재작성

### 레퍼런스 — j-cat.co.jp Project Story

실측한 구성입니다.

| 항목 | 값 |
|---|---|
| 콘텐츠 폭 | 1080 |
| 사진 | **723 × 506 — 폭의 67%** |
| 번호 | "Vol. 01" 작게 |
| 제목 / 본문 | 57px / 13px |
| 전환 | Splide 캐러셀로 슬라이드를 넘기면 사진이 바뀜 |

**사진이 주인공이고 글이 딸립니다.** ②의 아코디언은 사진이 행 안에 들어가
있어 260 × 300이 한계였는데, 그 관계를 뒤집어 사진을 무대로 올리고 목록은
인덱스로 내렸습니다.

### ★ 사진 크기 — 780 × 900이 이 에셋의 상한입니다

| | ② 아코디언 | ③ 1차 | ③ **현재** |
|---|---|---|---|
| 표시 크기 (1840+) | 260 × 300 | 560 × 650 | **780 × 900** |
| 넓이 | 78,000 px² | 364,000 px² | **702,000 px² (②의 9배)** |
| 원본 대비 배율 | 0.33 | 0.66 | **0.91 / 0.99 — 확대 없음** |

에셋은 785 × 928(consultation만 853 × 960)입니다. **780px이 원본에 딱 붙는
크기**라 다섯 장 모두 확대율이 1.0 이하입니다(실측 0.914 / 0.994 ×4).
**여기서 더 올리면 원본을 늘리는 것이라 오히려 뭉개집니다.**

세로 900은 비율 **1.154**로 원본 **1.182**와 거의 같습니다. 즉 잘라내는
부분이 거의 없습니다. 가로로 크롭하면(16:9 등) 인물 머리가 잘리고
"만들어 넣은 컷" 느낌이 강해져서 원본 세로 비율을 지켰습니다.

### ★ 사진 자체는 바꾸지 못했습니다

"AI가 만든 느낌"은 **파일 자체의 성질이라 코드로 바꿀 수 없습니다.**
이번에 한 것은 그 인상을 줄이는 표현 방식뿐입니다.

- 확대를 없앴습니다(0.33배 → 0.66배). 늘려 그린 사진 특유의 물렁한 가장자리가
  사라집니다.
- 원본 비율을 지켜 기계적으로 잘린 느낌을 없앴습니다.
- 색을 덧씌우지 않습니다. ②에서는 사진이 딥그린 위에 얹혀 있었습니다.
- 크게 그려서 실제 디테일(원단 결, 손, 주름)이 보이게 했습니다.

**진짜로 해결하려면 실제 촬영 사진으로 파일을 교체해야 합니다.**
교체할 때 `assets/main/`의 다섯 파일 이름을 그대로 쓰면 코드는 손댈 필요가
없습니다. 권장 크기는 **1560 × 1800 이상**(780 × 900의 2배, 레티나 대응)입니다.

### 구성

```
01  Consultation          ┌──────────────────┐
02  Design selection      │                  │
03  Fabric & measurement  │   사진 780 × 900  │
04  Tailoring             │                  │
05  Completion            │                  │
                          │                  │
Step 01 / 05              │                  │
Consultation   ← 32px     │                  │
설명 20px 3~4줄            └──────────────────┘
```

**번호 목록이 왼쪽 열 맨 위**에 오고 그 아래에 현재 단계의 글이,
오른쪽에 큰 사진이 옵니다(1024px 이상). 1700 기준 왼쪽 820 / 사진 780.

사진은 **DOM에서 먼저** 옵니다 — 좁은 화면에서 맨 위여야 하기 때문입니다.
넓은 화면에서는 `order: 1`이 오른쪽으로 보냅니다. 좁은 화면 순서는
사진 → 번호 목록 → 글입니다(실측 확인).

- 목록 행의 제목은 **본문 크기(20px)**입니다. 큰 제목은 위 무대에 있으므로
  목록에서까지 크면 둘이 싸웁니다.
- 행에 마우스를 올리면 ②와 같은 방식으로 옅은 포인트 색이 아래에서
  차오릅니다(`--process_fill_color`, 알파 0.16).

### ★ 높이를 JS로 재지 않습니다

②에서는 열린 칸 높이를 JS가 재서 맞춰야 했습니다. 지금은 필요 없습니다.

- 사진 상자가 **고정 크기**입니다(560 × 650).
- 글 다섯 벌을 **CSS grid 한 칸에 겹쳐** 두었습니다(`grid-area: 1 / 1`).
  가장 긴 글이 높이를 정하므로 단계를 옮겨도 무대 높이가 그대로입니다.
  1920에서 다섯 벌 모두 247px, 무대 높이 650px로 측정됐습니다.

### 반드시 지켜야 하는 것

1. **`--process_media_width`를 780보다 크게 올리면 안 됩니다.** 원본(785px)을
   넘기는 순간 확대가 시작돼 지금 얻은 선명함이 사라집니다.
2. **글은 `visibility`까지 함께 껐다 켭니다.** `opacity: 0`만으로는 겹쳐 있는
   비활성 글이 마우스와 스크린리더에 잡힙니다. `visibility`의 transition은
   지연을 줘서 페이드가 끝난 뒤에 꺼지게 합니다.
3. **행 사이는 gap이 아니라 선입니다.** gap을 쓰면 색이 차오를 때 행 사이가
   끊겨 보입니다.
4. **모바일에서는 사진에 고정 높이를 주지 않습니다.** `aspect-ratio: 785/928`로
   비율만 지킵니다. 고정 높이를 두면 좌우가 잘립니다.

## Begin 섹션 — 카드 hover로 사진 흐리기 + 글 등장 (2026-08-10)

카드 사진이 **처음부터 흐릿하게** 보이던 것을 고치고, 흐림과 글을 hover로 옮겼습니다.

- `index.html` — 카드 세 장의 글을 `.begin_card_content` 한 겹으로 묶고, 사진을 `.jpg`로 교체
- `css/bespoke.css` — begin 카드 hover 블록 추가
- `assets/main/material.jpg` · `timeline.jpg` · `contact.jpg` — 신규

JS는 건드리지 않았습니다. 이 섹션에는 원래 스크립트가 없고 hover는 CSS만으로 됩니다.

### ★ 흐릿함의 원인이 **두 개**였습니다 — CSS만 고치면 안 됩니다

1. `.begin_card_bg { opacity: 0.3 }`
2. **에셋 자체의 알파.** `material/timeline/contact.png`는 알파가 **전 픽셀
   정확히 76**(= 76/255 = 29.8%)으로 구워져 있었습니다. `alphaextract`로 재면
   min = avg = max = 76입니다.

둘이 곱해져서 **실제로는 9%**로 그려지고 있었습니다(1840px 이상에서는 CSS가
`opacity: 1`이라 29.8%). 그래서 **CSS만 고쳐서는 절대 선명해지지 않습니다.**

> RGB는 멀쩡했습니다(luma 1~250 전 범위). 그래서 합성하지 않고 **알파 채널만
> 버렸습니다** — `ffmpeg -vf "format=rgb24"`. 크림색 위에 합성하면 지금 보이는
> 흐린 그림이 그대로 구워지므로 **합성하면 안 됩니다.**
> PNG는 straight alpha라 RGB가 미리 곱해져 있지 않아 이 방법이 성립합니다.

```
ffmpeg -i <이름>.png -vf "format=rgb24" -q:v 2 <이름>.jpg
```

용량도 같이 줄었습니다: 359 → 78KB / 361 → 61KB / 307 → 63KB.
**PNG 3장은 마스터로 그대로 두었습니다.**

이전 세션의 "이미 흐리게 처리된 상태로 저장돼 있다"는 기록은 절반만 맞았습니다 —
흐린 것은 픽셀이 아니라 알파였고, 되살릴 수 있었습니다.

### 동작

| | 사진 | 스크림 | 글 |
|---|---|---|---|
| 기본 | 원본 그대로 (`filter: none`, `opacity: 1`) | 0 | `opacity: 0` |
| hover · focus | `blur(6px)` + `scale(1.06)` | 크림색 0.55 | `opacity: 1`, `translateY 6 → 0` |

- 전환은 전부 기존 토큰(`--duration_base` 0.4s / `--easing_base`)입니다. 그래서
  `prefers-reduced-motion`에서 토큰이 0.01ms가 되며 자동으로 즉시 전환됩니다.
- **글 묶음은 `opacity`로만 숨깁니다.** `display: none`이면 카드 높이가 hover
  전후로 달라집니다. 실측에서 600px로 고정 확인.
- **`scale(1.06)`이 필요합니다.** `blur()`는 가장자리를 반투명하게 만들어 카드
  테두리 안쪽에 옅은 띠를 남깁니다. 살짝 키워 그 가장자리를 밖으로 밀어냅니다
  (`overflow: hidden`이라 레이아웃은 그대로).
- 스크림은 `.begin_card::after`입니다. `::after`가 자식들보다 뒤에 그려지므로
  같은 `z-index: 0`에서도 사진을 덮고, 글(`z-index: 1`)보다는 아래입니다.

### ★ `:hover`와 `:focus-within`을 나눠 둡니다

`:hover` 규칙만 `@media (hover: hover) and (pointer: fine)` 안에 있습니다.
터치 기기에서 hover 상태가 눌린 채 남는 것을 막습니다.

**`:focus-within`은 미디어쿼리 밖에 있어야 합니다.** 카드 안에 버튼·링크가 있어서,
이걸 빼면 **보이지 않는 요소가 포커스를 받습니다.**

### 알아둘 것 — 터치 기기에서는 글이 안 보입니다

사용자 요청("hover가 없는 환경에서는 텍스트가 기본적으로 노출되지 않도록")을
그대로 따른 결과입니다. 360px에서 `(hover: hover)`가 false라 hover 규칙이 죽고,
글은 카드 안 버튼이 포커스를 받을 때만 나타납니다.

모바일에서 글을 보이게 하려면 아래 한 블록만 추가하면 됩니다:

```css
@media (hover: none) {
  .begin_card_content { opacity: 1; transform: none; }
  .begin_card_bg { filter: blur(6px); transform: scale(1.06); }
  .begin_card::after { opacity: 0.55; }
}
```

### 검증 (Chromium, localhost:5661)

- **기본 상태**: `filter: none` · `opacity: 1` · transform 없음 · 스크림 0 · 글 0.
  사진은 `material.jpg` 500 × 600으로 로드.
- **활성 상태**(트랜지션을 끄고 측정): `blur(6px)` · `scale(1.06)` · 스크림 0.55 ·
  글 1 · translate 해제.
- **해제 후 기본값과 완전히 일치**(깜빡임·잔여 상태 없음).
- **카드 높이 600px이 세 상태 내내 불변** — 레이아웃이 움직이지 않습니다.
- 카드 3장 전부 500 × 600(1920) 그대로, 360px에서도 크기·가로 스크롤 이상 없음,
  깨진 이미지 0, 콘솔 오류 0, CSS 중괄호 233/233.
- 1840 블록의 `.begin_card_bg { opacity: 1 }`은 이제 기본값과 같아 하는 일이
  없습니다. 그 블록의 "주석부터 파일 끝까지 삭제하면 되돌아간다" 계약을 지키려고
  지우지 않고 주석만 갱신했습니다.

### 확인하지 못한 부분

- **실제 마우스 hover를 직접 걸어보지 못했습니다.** 이 미리보기 패널이 프레임을
  합성하지 않아 좌표 기반 hover를 쓸 수 없습니다. 대신 (a) hover 규칙이 CSSOM에
  `(hover: hover) and (pointer: fine)` 조건으로 실제 존재하는 것과,
  (b) **선언이 완전히 동일한** `:focus-within` 경로가 위 표대로 동작하는 것을
  확인했습니다. **눈으로 보는 blur 세기(6px)와 스크림 농도(0.55)는 사용자 확인이
  필요합니다.**
- 트랜지션이 흐르는 모습(0.4초). 프레임이 돌지 않아 목표값만 읽었습니다.

## Begin 섹션 — `+` 핀으로 상세 열어 두기 (2026-08-10)

hover로만 보이던 상세 내용을, **`+` 핀을 눌러 열어 둘 수 있게** 했습니다.
레퍼런스는 `pages/shop_detail/`의 "Complete the Look" 섹션 `.look_pin`입니다.

- `index.html` — 카드 세 장에 `.begin_card_pin` 버튼 추가
- `css/bespoke.css` — 핀 스타일 + 열림 상태 규칙
- `js/bespoke.js` — `initBeginCards()` 추가

### shop_detail `.look_pin`에서 가져온 것

| 항목 | 값 |
|---|---|
| 크기 | 36px 정원 (`border: 0` / `border-radius: 50%`) |
| 배경 · 글자 | `#fffdf9` / 18px, 내용은 글자 `+` |
| 활성 | `transform: scale(1.15)` + 딥그린 배경 + 흰 글씨 |
| 전환 | `transform` · `background-color` · `color` |
| 동작 | `is_active` class 토글, `aria-expanded` 동기화, **한 번에 하나만**, Escape로 전체 닫기 |

딥그린은 `--detail_green`(#1f433f)과 **값이 같은** 이 페이지의 `--color_point`를 씁니다.
전환 시간은 이 페이지 토큰(`--duration_fast` / `--duration_base` + `--easing_base`)으로

### ★ 핀이 흐름 안으로 들어가 버리는 함정

기존 규칙 `.begin_card > *:not(.begin_card_bg)`가 특정도 (0,2,0)으로
`position: relative`를 강제해서, 핀의 `position: absolute`(0,1,0)를 **이깁니다.**
`:not(.begin_card_pin)`을 추가해 빼 줘야 합니다.

### ★ 닫힘/열림 위치를 `top`·`right` 한 쌍으로만 바꿉니다

닫힘은 `calc(50% - 크기/2)`(사진 정중앙), 열림은 모서리 16px입니다.
같은 속성끼리 오가므로 전환이 끊기지 않고, `transform`은 레퍼런스대로
`scale` 전용으로 남습니다.

**글이 보이는 상태에서는 핀이 반드시 비켜야 합니다.** 가운데 그대로 두면
`.begin_card_desc` 위에 겹칩니다(1280 미만에서 특히).

### ★ hover는 트리거가 아닙니다 (2026-08-10 최종)

**처음에는 hover로도 열렸습니다. 사용자 결정으로 걷어냈습니다** — 마우스가
지나가기만 해도 blur와 글이 뜨는 것이 의도와 달랐습니다. 지금 콘텐츠 상태를
바꾸는 것은 **핀 클릭 하나뿐**입니다.

없앤 것:
- `@media (hover: hover)` 안에 있던 `.begin_card:hover`의 blur · 스크림 · 글 ·
  핀 이동 네 규칙
- `:has(.begin_card_content:focus-within)` 조건

`:has()` 조건은 원래 "핀을 누르는 순간 포커스가 카드 안으로 들어와 **다시 눌러도
닫히지 않는**" 문제를 피하려고 좁혀 둔 것이었는데, hover를 걷어내면서 함께
없앴습니다. 대신 닫힘 상태의 키보드 접근은 **JS가 `tabindex`로** 처리합니다
(아래 참고).

hover가 지금 하는 일은 **핀 자신의 피드백뿐**입니다 —
`background: --color_surface_subtle` + `scale(1.08)`. 열림(딥그린 + `scale(1.15)`)과
톤이 달라 서로 헷갈리지 않고, 열려 있을 때 hover가 딥그린을 되돌리지 않도록
`.begin_card.is_open .begin_card_pin:hover`로 한 번 더 눌러 두었습니다.

### ★ 닫힘 상태에서 글 안쪽 링크를 Tab 순서에서 뺍니다

글은 `opacity: 0`으로만 숨겨져 있어서, 그대로 두면 **보이지 않는 버튼·링크가
포커스를 받습니다.** `setOpen()`이 `aria-hidden`과 함께
`link.tabIndex = shouldOpen ? 0 : -1`을 관리합니다. shop_detail의
`.look_product`가 하는 것과 같은 처리이고, 페이지 로드 시에도 한 번 돌려
초기 상태를 맞춥니다.

### 상태

| | 사진 | 글 | 핀 |
|---|---|---|---|
| 기본 | 원본 그대로 | `opacity: 0`, `tabindex -1` | 크림, 사진 **정중앙**, `+` |
| 핀 hover | **변화 없음** | **변화 없음** | 옅은 톤 + `scale(1.08)` |

마우스가 카드 밖으로 나가도 열린 상태가 그대로 남습니다(hover와 무관하므로).

- **실제 마우스 hover와 손가락 탭을 직접 해 보지 못했습니다.** 이 미리보기
  패널이 프레임을 합성하지 않아 좌표 기반 입력을 쓸 수 없습니다. 클릭은
  `element.click()`으로 확인했습니다.
  "hover로는 열리지 않는다"는 쪽은 더 확실합니다 — **CSSOM을 전수 검사해
  `.begin_card`의 hover·focus 조건으로 사진·글·스크림을 바꾸는 규칙이
  0개**임을 확인했습니다(핀 자신의 피드백만 남음). 규칙이 없으므로 마우스를
  올려도 열릴 방법이 구조적으로 없습니다.
  다만 **핀 hover 피드백의 세기(옅은 톤 + 1.08)는 눈으로 봐야 합니다.**
- 전환이 흐르는 모습. 프레임이 돌지 않아 목표값만 읽었습니다.

## Materials — 원단 사진을 원본 JPG로 교체 + 클릭 즉시 표시 (2026-08-10)

위 「Materials 섹션」 항목의 **트리거와 전환이 뒤집혔습니다.** 그 항목의
"hover로 바뀐다" · "흐렸다가 갈아 끼운다" · "`is_fading`"은 **더 이상 사실이
아닙니다.** 아래가 현재 동작입니다.

- `index.html` — 원단 사진 7곳(`src`) 교체
- `css/bespoke.css` — `.materials_texture img`의 페이드 제거
- `js/bespoke.js` — preload 추가, `mouseover`·`focusin` 위임 제거, 즉시 교체

다른 해석의 여지가 없었습니다.

**옛 PNG 6장은 지우지 않았습니다.** 이제 어디서도 참조하지 않습니다.

> 위 「원단 사진이 원본보다 크게 그려집니다」 항목이 지적한 문제가
> 이걸로 사라졌습니다 — 180 × 200을 466 × 678로 늘려 그리던 것이
> 이제 원본이 표시 크기보다 훨씬 큽니다.

### ★ 대신 이 섹션 하나가 13MB입니다

원본 카메라 파일을 그대로 쓰기로 한 **사용자 결정**입니다(화질을 건드리지
말 것). 표시 크기는 큰 사진 466 × 678, 스와치 180 × 200뿐이라 실제로 필요한
화소의 수십 배입니다. **웹용 축소본을 만들면 약 0.6MB로 줄어듭니다** —
사용자가 "이후 필요하면 별도로 생성하는 방향"으로 남겨 둔 다음 작업입니다.
`docs/PROJECT_CONTEXT.md`의 shop 갤러리 항목과 같은 방법을 쓰면 됩니다.

### 2) 트리거는 클릭 하나뿐입니다

`initMaterialsSelector()`가 등록하는 사용자 이벤트는 **`click` 하나**입니다
(나머지는 preload의 `load`·`error`, 재측정용 `resize`).

- **`mouseover` 위임을 지웠습니다.** 사진이 장당 1~4MB가 되면서 마우스가
  스쳐 지나가기만 해도 큰 사진이 갈아 끼워지는 게 손해가 됐습니다.
- **`focusin` 위임도 같이 지웠습니다.** Tab으로 지나가기만 해도 바뀌는 것은
  "클릭으로만 바뀐다"는 규칙과 어긋납니다. `<button>`이라 **Enter·Space가
  click을 그대로 발생시켜 키보드 경로는 그대로 살아 있습니다.**
- 스와치 버튼의 `:hover { opacity: 1 }`은 그대로 뒀습니다 — 사진을 받거나
  바꾸지 않는 시각 피드백뿐입니다.

### 3) ★ "눌렀는데 한참 비어 있다"의 원인은 페이드였습니다

이전 구현은 `is_fading`으로 큰 사진을 **0.4초에 걸쳐 opacity 0까지 흐린 뒤**
`src`를 갈아 끼웠습니다. 그 0.4초가 화면에서는 **빈 자리**로 보입니다.
사진이 원본 JPG로 커지면서 그 뒤에 받는 시간까지 더해져 증상이 심해졌습니다.

고친 것 두 가지입니다.

1. **페이드를 없앴습니다.** `.materials_texture img`의 `opacity` /
   `transition`을 지웠습니다(계산값 `transition-duration: 0s` 확인).
   **여기에 opacity transition을 다시 넣으면 증상이 그대로 돌아옵니다.**
2. **여섯 장을 미리 받아 둡니다.** `initMaterialsSelector()` 초기화에서
   스와치 마크업의 `src`를 읽어 `new Image()`로 preload합니다. 목록을 JS에
   박아두지 않았으므로 사진을 바꿔도 여기를 고칠 필요가 없습니다.
   **이 섹션이 실제로 쓰는 6장만** 대상입니다.

### ★ 아직 안 받아진 사진이면 `src`를 바꾸지 않고 기다립니다

preload가 끝나기 전에 눌렸을 때를 위한 안전장치입니다. 바꿔 버리면 받는
동안 `<img>`가 빈 상자가 되어 **고치려던 그 증상이 그대로 재현됩니다.**
지금은 `complete`가 참일 때만 즉시 넣고, 아니면 그 `Image`의 `load`를 기다립니다
— 기다리는 동안 **직전 원단 사진이 그대로 떠 있어 화면이 비는 구간이 없습니다.**
`error`에도 같은 처리를 걸어, 깨진 파일이면 영영 기다리지 않고 넣습니다
(그래야 `alt`가 읽히고 문제가 드러납니다).

경합 방지 토큰(`textureToken`)은 그대로입니다.

### 4) 예약 페이지(`reservation.html`)의 원단 카드도 같은 사진으로

`reservation_fieldset` 중 **원단 6장만** 바꿨습니다. 대응 관계는 위 표와 같고,
이쪽 파일명은 `assets/reservation/silk · cotton · linen · ramie · traditional ·
seasonal_fabric.png`였습니다(정확히 일치한 건 cotton · linen · seasonal_fabric 셋).

- **파일을 복사하지 않고 `assets/main/`의 같은 파일을 함께 씁니다.**

## 예약 폼 선택 카드 — 체크 배지 + 레이아웃 고정 (2026-08-10)

`.bespoke_choice`의 선택 표시를 **글자에서 배지로** 바꾸고, 선택을 옮길 때
카드와 `.common_container`가 움직이던 문제를 없앴습니다.

- `reservation.html` — `.bespoke_choice_mark` span 9개 제거
- `css/bespoke_base.css` — 배지·누름 모션·흐리기 추가, mark 규칙 제거

### ★ 원인 하나로 두 증상이 같이 났습니다

`.bespoke_choice_mark`는 이름 옆에 끼워 넣은 **" — selected" 글자**였습니다
(평소 `width: 0; overflow: hidden`, 선택되면 `width: auto`). 이것이:

1. **긴 이름을 두 줄로 넘겨 카드를 +30px 자라게 했습니다.**
   짧은 이름(Durumagi)은 한 줄에 들어가서 카드마다 결과가 달랐습니다.
2. **폭이 0이어도 인라인 블록이라 줄 상자를 7px 부풀리고 있었습니다**
   (이름 높이 37 → 제거 후 **30** = 글꼴 24 × 1.25 그대로).
3. 글자가 늘 DOM에 있어 **읽기 도구가 모든 카드에서 "selected"를 읽었습니다.**

1280에서 잰 실제 증상 — 선택을 옮길 때마다 컨테이너가 튑니다:

| 선택 | 카드 높이 | 컨테이너 |
|---|---|---|
| Jeogori & Chima | **495** / 465 / 465 | 773 |
| Durumagi | 465 / 465 / 465 | **743** |
| Modern Hanbok | 465 / 465 / **495** | 773 |

### 지금 — 세 상태가 완전히 같습니다

| 선택 | 카드 높이 | 그리드 | 컨테이너 | 문서 |
|---|---|---|---|---|
| Jeogori & Chima | 458 / 458 / 458 | 458 | 736 | 6942 |
| Durumagi | 458 / 458 / 458 | 458 | 736 | 6942 |
| Modern Hanbok | 458 / 458 / 458 | 458 | 736 | 6942 |

이름·설명의 top 좌표까지 세 상태에서 동일합니다. **요청의 1번("컨테이너 고정")과
2번(`is_three_up` 클릭 버그)이 이 하나로 같이 해결됩니다** — 컨테이너를
`position: fixed`로 붙든 것이 아니라, **움직일 이유를 없앤 것**입니다.

> 부수 효과: 위 7px 때문에 카드가 전체적으로 조금 낮아졌습니다 —
> 실루엣 465 → **458**, 원단 378 → **371**. 모든 카드에 똑같이 적용되고
> 선택과 무관하게 고정입니다.

### 선택 표시 — 오른쪽 위 체크 배지

가짜 요소 두 개로 그립니다. **글 흐름 밖(`position: absolute`)이라
이름·설명·카드 크기에 영향이 없습니다.**

- `::before` — 지름 28px 원, `--color_text_inverse`(밝은 크림).
  카드 오른쪽 위 안쪽 16px.
- `::after` — 체크. `border-left` + `border-bottom`만 남긴 11 × 6 상자를
  `rotate(-45deg)`. 색은 `--color_point`.
  **가로가 세로보다 길어야** 체크의 긴 획이 오른쪽 위로 뻗습니다.
- 나타날 때 `opacity 0 → 1` + `scale(0.7) → 1` (`--duration_fast`).

**아이콘 파일을 만들지 않았습니다** — 저장소에 체크 아이콘이 없고,
이 정도 도형은 CSS로 그리는 편이 낫습니다(이모지도 쓰지 않습니다).

배지에 **`pointer-events: none`이 필수입니다.** 없으면 배지가 라벨 클릭을
가로챕니다. 배지 한가운데 좌표에서 잡히는 요소가 여전히 카드 안쪽
`<img>`임을 확인했습니다.

### 고르는 느낌과 흐리기

- 누르는 동안 `:active { transform: scale(0.985) }`.
- 선택되면 `bespoke_choice_settle`이 한 번 돕니다 — `0.985 → 1.012 → 1`.
- 고르지 않은 카드는 `opacity: 0.82`. 마우스를 올리면 1로 돌아옵니다
  (`@media (hover: hover) and (pointer: fine)` 안에 있어 터치에서
  눌린 채 남지 않습니다).

**★ `transform`과 `opacity`만 씁니다.** 둘 다 레이아웃을 다시 계산하지 않아

### ★ 붙는 자리는 0이 아니라 헤더 아래입니다

띠가 실제로 붙기 시작하니 **공통 헤더가 100% 덮었습니다** — 헤더는
`position: fixed` `z-index: 50`, 띠는 `z-index: 30`이라 둘 다 top 0에서

(로고와 메뉴가 사라집니다).

CSS는 `top: var(--header_height)`로 두고, **JS가 헤더의 실제 높이로 덮어씁니다.**
헤더가 `min-height`라 내용에 따라 토큰보다 커지기 때문입니다 — 1280에서
토큰 64 / 실제 66이라 2px이 가려졌습니다.

`initStepsOffset()`이 두 가지를 처리합니다. **둘 다 실제로 걸렸던 문제입니다:**

1. **헤더가 아직 없습니다.** common.js가 `fetch`로 끼워 넣는데 그게 `load`보다
   늦을 수 있어 `load` 한 번으로는 놓쳤습니다. → 슬롯을 `MutationObserver`로
   지켜보다가 들어오는 순간 잽니다.
2. **막 들어온 헤더는 아직 64px입니다.** 로고 이미지가 뜨면 66px이 됩니다.

   달아 크기가 바뀔 때마다 따라갑니다.

JS가 없으면 CSS의 토큰 값이 그대로 쓰입니다(1280에서 2px 겹침).

### 이 페이지의 고정 UI는 둘이고 성격이 반대입니다

| | 헤더 | 진행 단계 띠 |
|---|---|---|
| 자리 | `position: fixed` `top: 0` `z-index: 50` | `position: sticky` `z-index: 30` |
| 동작 | 스크롤 방향에 따라 **나타났다 사라짐** | **언제나 보임** |
| 숨김 방식 | `transform: translateY(-100%)` | — |

**둘 다 유지해야 하는 동작입니다.** 헤더를 항상 보이게 바꾸지도, 띠의 고정을
없애지도 않았습니다. `common/js/common.js`와 `common/css/layout.css`는
**한 줄도 건드리지 않았습니다.**

### ★ 원인 — 중복 보정이 아니라 sticky 기준점이 헤더 상태를 몰랐습니다

헤더 높이를 문서 흐름에서 잡아 주는 곳은 **한 곳뿐**입니다 —
`common/css/common.css`의
`body[data-header-variant="black"] .common_header_slot { min-height: var(--header_height) }`.
이 슬롯은 문서 맨 위에 있고, 스크롤 0에서는 헤더가 항상 표시 상태이므로
(`updateHeaderOnScroll`이 `scrollY <= 16`에서 `is_hidden`을 뗍니다) 언제나
맞습니다. **`.reservation_hero`의 `padding-top`(64 / 130)과 띠의
`margin-top`(56 / 120)은 헤더 보정이 아니라 디자인 여백입니다.**

문제는 띠였습니다. `top`이 헤더 높이로 **고정**돼 있었는데,

> **헤더는 `transform`으로 사라집니다 — 자리를 비우지 않고 그림만 치웁니다.**

그래서 헤더가 사라져도 띠는 그대로 그 높이 아래에 남고, 그 사이 빈 띠로
내용이 지나갔습니다.

### 고친 방법 — 기준값 두 개로 전부 계산합니다

`.reservation_form`에 변수 세 개를 둡니다. **폭마다 px를 박아 두지 않습니다.**

| 변수 | 뜻 | 채우는 곳 |
|---|---|---|
| `--steps_header_h` | 헤더의 **실제** 높이 | JS 실측 (CSS 대비값 `var(--header_height)`) |
| `--steps_bar_h` | 띠의 **실제** 높이 | JS 실측 (CSS 대비값 72px) |
| `--steps_top` | 띠가 붙는 자리 | 헤더가 숨으면 **0**, 보이면 `--steps_header_h` |

```
헤더 표시 → [헤더][띠][내용]
헤더 숨김 → [띠][내용]
```

- `.reservation_steps { top: var(--steps_top) }` + `transition: top`으로
  헤더가 미끄러지는 것과 같은 길이·곡선으로 따라 올라갑니다.
  **붙어 있지 않은 동안에는 `top`이 아무 일도 하지 않으므로** 페이지 위쪽
  레이아웃은 그대로입니다(음수 margin이나 spacer를 쓰지 않은 이유).
- 앵커 여백도 같은 값에서 나옵니다 —
  `scroll-margin-top: calc(var(--steps_header_h) + var(--steps_bar_h) + 12px)`.
  **폭별 하드코딩 3개(200 / 156 / 136)를 지웠습니다.**
  `--steps_top`이 아니라 `--steps_header_h`를 쓰는 이유: 뛰는 도중 헤더가
  나타날 수 있으므로 **헤더가 보이는 경우를 기준**으로 잡아야 안전합니다.

**헤더를 실측하는 이유**: 토큰 `--header_height`(64 / 72 / 64)은 `min-height`라
내용에 따라 헤더가 더 커집니다 — 1280에서 실제 **66px**입니다.

`initStepsOffset()`이 지켜보는 것 세 가지(전부 실제로 필요했습니다):

1. **슬롯** (`MutationObserver`) — 헤더는 common.js가 `fetch`로 넣는데
   `load`보다 늦을 수 있어 놓칩니다.
2. **헤더·띠 크기** (`ResizeObserver`) — 막 들어온 헤더는 로고 전이라 64px이고
   로고가 뜨면 66px이 됩니다. 띠도 폭에 따라 줄 수가 달라집니다.
3. **헤더의 class** (`MutationObserver`) — `is_hidden`이 붙었다 떨어질 때마다
   `--steps_top`을 바꿉니다. common.js는 공용 파일이라 **건드리지 않고
   결과만 지켜봅니다.**

JS가 없으면 CSS 대비값이 쓰여 지금까지처럼 헤더 아래에 고정됩니다.

## 1920에서 여백이 넓어 보이던 원인 — 공통 zoom 0.75 (2026-08-10)

"1920 × 1080 / 100%에서 콘텐츠가 작아 보이고 좌우 여백이 과하다"는 지적입니다.
**여백을 줄여서 고친 것이 아니라, 이중으로 걸려 있던 축소를 끊었습니다.**

- `css/bespoke.css` · `css/bespoke_base.css` — 각각 블록 하나(31줄)

### ★ 원인 — `html { zoom: 0.75 }`가 이 페이지까지 걸려 있었습니다

```css
@media (min-width: 1850px) and (max-width: 1990px) {
  :root { --site_view_scale: 1; }
}
```

  **둘 다 함께 1**이 됩니다(푸터 슬롯 zoom 1.333 → 1 확인).
- **`common/`은 건드리지 않았습니다** — Shop·Brand·Main은 그대로 0.75입니다

  있어서 공통을 되돌리면 그쪽이 깨집니다.
- **두 파일에 같은 블록이 들어갑니다.** `index.html`은 `bespoke.css`를,
  예약·완료는 `bespoke_base.css`를 부릅니다. **한쪽만 고치면 세 페이지의
  크기가 서로 달라집니다.**

## 75% 화면 스케일에 맞춘 레이아웃 밀도 재조정 (2026-08-10)

`common/css/common.css`가 1850~1990px에서 `html { zoom: 0.75 }`를 겁니다
(커밋 `0765b4b`). **이 축소는 유지하기로 했습니다**(사용자 결정).
대신 **여백·폭·타이포 값을 그 환경에 맞게 다시 잡았습니다.**

> 이전 시도에서 `--site_view_scale: 1`로 축소를 꺼 버렸는데, 그건 결국
> "전체를 다시 확대"하는 것이라 요청과 어긋나 되돌렸습니다.

- `css/bespoke.css` — 캔버스 단위 도입, 1840 블록 46곳 변환, 끝에 뷰포트 단위 블록
- `css/bespoke_base.css` — 캔버스 단위 + 레버 블록(파일 끝)
- `css/reservation_done.css` — 지도 max-width 1줄

### ★ 원인 — 값이 1920 캔버스에 고정돼 있었습니다

zoom 0.75가 걸리면 레이아웃이 쓰는 폭은 1905가 아니라
**1905 ÷ 0.75 = 2540 CSS px**입니다. 그런데
`--layout_inner`(1600) · 1840 블록의 컨테이너(1700) · 타이포 clamp 상한
(64/48/32/24/20px)이 전부 **1920 캔버스 기준 절대값**이라, 넓어진 캔버스의
가운데 63~67%만 쓰고 좌우를 비웁니다. 글자도 화면에서는 0.75배로 보입니다.

즉 **개별 섹션 문제가 아니라 공통 레버 문제**였습니다.

### 고친 방법 — 시안 단위 `--bespoke_unit`

```css
:root { --bespoke_unit: 1px; }                 /* 평소 */
@media (min-width: 1850px) and (max-width: 1990px) {
  :root { --bespoke_unit: calc(1px * calc(1 / var(--site_view_scale))); }
}
```

1840 블록의 시안 px를 전부 이 단위로 바꿨습니다 —
`gap: 179px` → `gap: calc(179 * var(--bespoke_unit))` (46곳, 스크립트로 일괄).
**숫자는 시안값 그대로 읽히고**, 배수는 `--site_view_scale`에서 끌어오므로
공통 파일에서 0.75를 바꾸면 여기도 따라갑니다.

같은 방식으로 `--layout_inner` · `--layout_gutter` · `--fs_*` 9개 ·
`--bespoke_section_gap` · `--bespoke_head_gap` · `--bespoke_fs_*` 3개를
zoom 구간에서만 키웁니다.

### ★★ 뷰포트 단위는 zoom을 따라가지 않습니다

실측: zoom 0.75에서 `height: 100svh`인 상자가 화면 1080px 중
**810px(75%)**만 덮었습니다. `svh`/`vh`/`vw`는 물리 뷰포트 크기를 그대로
CSS px로 주고, 거기에 zoom이 곱해집니다.

그래서 **sticky 무대 둘(wordmark · atelier)이 화면 아래 4분의 1을 비우고**
있었습니다. `calc(100svh * var(--bespoke_canvas))`로 되돌렸습니다.

### ★ 두 블록은 반드시 파일 **맨 끝**에 있어야 합니다

처음에 파일 앞에 뒀다가 조용히 무효가 됐습니다(실제로 겪음).
`.philosophy` 같은 선택자는 위쪽 규칙과 특정도가 같아 **소스 순서로만**
이깁니다. philosophy는 한 단계 더 필요했습니다 — 기존 규칙이
`.main .philosophy`(0,2,0)라 `.main`을 붙여야 이깁니다.

### ★ 푸터는 제외합니다

공통 파일이 `.common_footer_slot`에 `zoom: calc(1 / --site_view_scale)`로
역보정을 걸어 두어 푸터만 원래 크기입니다. 거기까지 값을 키우면 2133px이
1905 화면을 넘겨 **가로 스크롤이 생기고 글자도 커집니다.**

## materials 큰 사진을 오른쪽 글 열 높이에 맞춤 (2026-08-10)

`.materials_texture_img`가 오른쪽 글 열보다 짧아 아래가 비어 있었습니다.
**변경은 `css/bespoke.css`의 `.materials_texture` 한 규칙**입니다.

### 원인 두 가지

1. **`align-self: flex-start`가 늘어나지 못하게 막고 있었습니다.**
   주석에 이유가 적혀 있었습니다 — *"사진 원본이 180 × 200뿐이라 더 늘리면
   그만큼 더 잘리고 흐려진다"*. **그 전제가 사라졌습니다.** 원단 사진을
   원본 JPG(3024 × 4032 ~ 4016 × 6016)로 교체해서 이제 얼마를 늘려도
   원본 화소가 남습니다.
2. **폭이 고정 px(`flex: 0 0 466px` + `max-width: 466px`)이라 75% 화면에서
   혼자 줄어 있었습니다.** 1920에서 글 열은 캔버스 단위로 커졌는데 사진만
   466 × 0.75 = **350px**이라 세로도 509px에 머물러 **322px 어긋났습니다.**

### 고친 내용

```css
@media (min-width: 1280px) {
  .materials_texture {
    flex: 0 0 calc(466 * var(--bespoke_unit));
    max-width: calc(466 * var(--bespoke_unit));
    align-self: stretch;
    aspect-ratio: auto;
  }
}
```

- **`aspect-ratio`를 꺼야 stretch가 삽니다.** 폭이 정해진 상자에 비율이
  남아 있으면 그 비율이 높이를 정해 버려 `align-self: stretch`가 아무 일도
  하지 않습니다.
- **`max-width`도 같이 풀어야 합니다.** 기본 규칙의 `max-width: 466px`가
  남아 있으면 `flex-basis`가 621px이어도 466px에서 잘려 폭이 안 커집니다
  (실제로 한 번 걸렸습니다).
